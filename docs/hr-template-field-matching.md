# 人事资料字段建议

应用模板与表格导入复用 `shared/hrFieldMatching.js` 的标题得分与显式别名。副本分别位于小程序 `utils/hrFieldMatching.js` 和服务端 `core/services/hrFieldMatching.js`，运行时不跨目录依赖。修改唯一源后运行 `node scripts/sync-hr-field-matching.js --write`；不带参数为一致性校验，回归测试也执行此检查。

## 推荐与默认处理

- 完全同名优先（1.0）；显式同义标题次之（0.95），包括手机号/手机号码/联系电话、邮箱/电子邮箱/电子邮件、身份/职位/身份类别及登记的英文写法。
- 子串关系（0.75）与字符 Jaccard 相似度（最低 0.4）沿用导入的得分思想，但应用模板只能作为提示，不默认应用。紧急联系人、家庭、备用等修饰不会被移除；不能把“紧急联系人手机号”默认当本人手机号。
- 应用模板只在字段类型完全相同、候选唯一且没有多个源字段争用同一目标时，返回 `suggestedDefault: true`。同分多候选不给出确定建议；多源冲突不默认，留给用户调整。
- 前端预填“应用模板”及建议目标，用户仍可更改或取消；打开窗口只读取，不迁移数据。旧接口没有 `suggestedDefault` 时，仅唯一精确同名且同类型的建议可默认，其他建议仍需人工选择。
- 非默认建议不等于“不匹配”：管理员可以在原有兼容范围内手动选择，之后仍须通过现有预检、逐值校验、确认令牌及事务复核。无效后续项不得部分保存。

## 不可跨越的边界

保存共享模板定义只更新模板库，不自动更新任何组织已应用的资料设置。保存成功后明确说明“模板库已保存”；有当前组织应用权限时，可由用户明确选择检查当前组织的处理方案，无应用权限不显示此入口。取消后续操作仍保留已保存的模板库修改。后续入口只读取并打开现有应用窗口，不直接执行应用；页面隐藏、卸载、切换组织或权限失效后，旧保存响应与旧确认回调均作废。

将文本改为数字或序列后，模板库回读必须呈现新的类型和选项；当前组织仍使用旧类型直至明确应用。类型不同不默认搬运已有资料，管理员选择目标后必须执行逐值预检，数字格式或序列范围不兼容时拒绝整单应用。保存失败保留编辑草稿并展示服务端受控原因，不能把定义保存失败或尚未应用掩盖为笼统成功。

此功能只对资料列标题提供草稿建议，不改真实岗位、身份类别字典、人员识别或权限。身份/职位相近只是模板标题语义，不授予任何 assignment；多个身份/职位目标无法唯一确定时必须人工选择。

全局资料唯一键仍为自然人、去首尾空格后的字段名与完全一致的字段类型。禁止使用相似度、别名字典或建议结果模糊合并实际数据；历史值只在用户明确确认模板处理后，按已有映射事务移动。

## 验证

`node scripts/hr-template-switch-suggestion-test.js` 覆盖电话、邮箱、身份/职位正例及类型不符、修饰词、多候选、多源冲突、旧接口降级、草稿覆盖和取消。脚本加载真实前端 Behavior 验证打开只读及请求动作，不连接生产数据库。

`node scripts/hr-template-save-continuation-test.js` 覆盖真实保存参数、明确确认后只打开处理窗口、取消、无应用权限、业务失败保留草稿、重复提交以及离页/切换组织/迟到回调隔离。

既有服务端模板校验与迁移测试仍必须执行。隔离脚本不能替代实际提交回读、真机操作与部署；交付时分别报告执行范围，不把生成建议当成资料已经保存。
