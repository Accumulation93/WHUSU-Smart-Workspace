## 保存回读与角色验证

`server/test/helpers/authorizationConsistencyCases.js` 由既有普通岗位委托 helper 调用，后者已接入完整集成测试。

1. 普通无分配资格岗位取得本人只读管理响应：canManage=false、canInspectOwn=true、canInspectOthers=false、canManageDelegations=false，管理规则、身份、资格列表为空；本人查询成功，他人查询403。
2. 普通管理员只有业务权限时同样不能分配；独立获授一个岗位的查询权后可查该岗位。以逐记录禁止覆盖唯一可查对象后，access 与 management 两处的查询他人标志都为false，实际查询403。

4. 缺失/错误资格编号、选错资格、跨资格拼接能力、移除资料项限制、移除期限、撤销后保存全部403，组织授权状态没有写入。原有省略资格编号合法请求仍按原有单项资格兼容执行，不能借省略编号跨资格完成整单修改。
5. 当前已发布身份可用但新草稿超出权限时，身份仍可见，canEdit/canPublish=false；再次分配实际使用发布版成功，没有把新草稿功能写入授权。

## 全关联检查与历史兼容

- 两条规则分别属于不同资格时，各自canEdit=true，但共同引用身份的canPublish=false。显式选择第一项、第二项或省略资格编号发布均403；发布历史仍只有原1版。跨两项资格整单删除也拒绝，保留全部原规则。
- 超级管理员发布与关联规则资料项不兼容的草稿，canPublish=false；真实发布返回400且数据库状态不变。
- 新规则、新身份及新分配资格均不能新增systemControlled管理动作。历史规则和身份原有受控值可以保留，继续增加另一受控动作或把历史身份用于新授权均拒绝。实际查询目录将受控动作标记为true，独立他人查询能力标记为false。
- 管理身份使用相对岗位same条件的新授权实际拒绝。旧same规则的编辑入口仍可用于修正条件，不将canEdit解释为原样保存必定成功。
- 前轮普通岗位委托、本人及动态本人修改、方案发布/恢复自授权、转授拒绝、同人不同岗位、治理资格创建/历史损坏拒绝、到期和撤销测试继续通过。

历史版本只读修复追加验证后完整集成再次退出码0：同一身份的第1版读取功能与第2版修改功能分别属于2项独立资格，查询历史同时返回第2、1版且不改变数据库状态；把第2版恢复为第1版仍因单项资格不能同时覆盖修改前后而403。历史受控功能版本可读取；移除受控功能并发布新版本后，旧版仍可读取，但恢复旧版重新引入受控功能返回403。源码核对独立只读参数仅在schemeVersions的2处校验传入，发布、恢复和整单删除继续执行单项资格约束。

## 最小查询数据

本人权限解释只返回规则范围实际引用的部门与性质名称；assignments/adminGrants为空。仅引用的动态资料项获得fieldLabels，未引用部门与资料项不在响应中；没有下发学号、人员编号或完整编辑目录。字段名称测试不涉及个人补充资料值。

追加审查后再次完整运行集成测试，退出码0：他人查询候选排除当前工作角色本身，但同一人的其他岗位和管理身份仍按权限独立保留。仅获准查询当前管理身份时，两处canInspectOthers标志均为false，候选为空，本人查询仍成功。旧测试要求超管候选包含自己的断言已改为排除当前grant并保留同人regular管理身份，其他隐私与岗位数量断言不变。

查询接口保留原fields协议并新增displayFields作为展示投影。实际验证普通岗位的历史显式studentId及受保护动态资料项得到空displayFields；fields=null时展开当前可用资料项并剔除保护项。fieldLabels不包含受保护动态资料项名称。管理员查询该普通岗位得到相同投影，不能按查询者的管理员身份放宽；管理员查询本人工作角色的人事读取能力仍可展示studentId。新建表单目录提供adminOnlyFields供按目标角色筛选，未改变历史保存协议及业务字段计算。

## 审查发现及处理

独立审查额外指出并由主 Agent 修正：查询入口标志不能只看存在允许能力；一次发布与整单删除必须在同一项资格内完成；可用发布版不能随不可编辑草稿一起隐藏；发布按钮必须核验关联规则的范围/资料项兼容性。这些修复已有上述实际拒绝与成功用例，不以源码存在替代执行。
