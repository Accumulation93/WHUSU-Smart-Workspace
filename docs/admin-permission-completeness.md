# 管理员权限补齐与业务记录清理

## 本轮范围与用户决定（2026-10-16）

用户明确要求超级管理员和被授权普通管理员能够永久删除业务记录及附件，以清理测试数据。普通用户保留原有撤回/取消权限。仅保留最小内部删除审计，不保留可恢复的业务副本；备份遵循原有保留期，不能把在线删除描述为清除了所有离线备份。

现场验证前变更必须写入主项目。用户已明确同意本轮运行一次本机完整 CI，生产只读验证，不以真实生产记录做删除测试。

## 已核对的缺口

- 当前目录为 7 组、33 项权限、183 条路由规则（`server/src/core/services/adminPermissions.js`）。多项查看、修改和删除绑定同一开关，授权者无法授予仅查看或明确的删除权限。
- `scripts/admin-route-permission-audit.js` 只扫描部分管理员调用与首个 POST 路由字符串，报告缺失 0 项不代表功能完整；数组别名、其他方法、自检权限和页面动作需要独立核对。
- 审核缺少管理员删除接口；`audit_signing_evidence` 对申请、步骤、附件使用 RESTRICT，不能直接调用原 `auditSubmission.remove`。
- 审核删除还必须清理全部轮次、签署证据、原文件及历次签署文件、已读标记、通知与未投递通知。磁盘清理需要可重试的持久任务，不能在数据库提交前删文件。
- 场地借用具有发起组织和审批组织，日程的跨组织可见不等于删除授权；删除必须与借用写入、审批和占用释放协调。
- 评分已有 `revokeScoreRecord`，实际删除答案和记录，但尚未统一最小删除审计与事务内权限复核。

## 实施要求

1. 保留既有模块查看与维护权限及独立导出、审核权限；将永久删除从原维护权限拆出。当前目录扩展为 7 组、49 项：14 项基础配置删除权限，新增审核记录、借用记录删除权限，评分记录沿用 `scoring.results_revoke`。超级管理员默认全部开放，普通管理员的新删除权限默认关闭。删除权限仅附带定位目标所需的读取，不附带新增、编辑或审批。
2. 旧权限键保留兼容，不能凭旧的查看或编辑权限自动授予新删除权限。授权普通管理员只能授出自己持有且可转授的权限，不得修改自身或超级管理员权限。
3. 删除入口先显示具体记录与不可恢复提示，服务端再次校验当前账号、管理角色、组织和独立删除权限；事务内重查权限并锁定记录。重复请求不能重复产生审计，失败必须整单回滚。
4. 审核删除是用户明确授权的历史不可变规则例外，仅限专用管理员清理接口；普通审批、编辑、撤回和重新提交仍不能删改历史。
5. 最小审计只保存组织、记录类型与编号、操作者标识、时间及结果，不复制正文、签名图片或文件内容。文件清理按已核验路径逐项执行，拒绝越界、符号链接和仍被其他记录引用的文件。
6. 删除后列表、待办、通知、统计和缓存都要更新；迟到通知不得重新生成已删除记录的入口。权限撤销与切换角色后前端立即停止旧操作，后端始终独立检查。
7. 人员、组织、岗位字典等被其他有效业务引用的基础数据保留引用保护；本轮记录清理不等于允许任意级联删除整个组织或账号。

## 验证与交付状态

源码已写入主项目。隔离 MySQL/HTTP 测试覆盖两轮 PDF、4 个物理附件与签署证据删除、跨组织拒绝、重复执行、权限撤销、角色不混用、记录版本变化拒绝、场地双组织通知清理和权限保存回读；文件清理专项覆盖路径边界、符号链接、共享引用与失败重试。浏览器测试覆盖审核与借用记录确认取消、业务拒绝和成功回读，以及活动、部门、印章、用途的维护与删除权限分离。测试源为 `server/test/adminRecordDeletion*.test.js`、`adminRecordFileCleanup.test.js` 与 `web/tests/e2e/admin-record-deletion.spec.js`。

本机完整 CI、主项目本轮微信编译和生产发布仍待执行完成；手机、Pad 竖屏和横屏尚未完成现场验证。现有模块维护权限仍合并读取与编辑，本轮没有新增所有模块的独立只读角色，不能将本轮称为全量只读权限拆分。
