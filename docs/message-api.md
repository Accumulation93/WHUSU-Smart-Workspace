## 2026-11-24 通知使用当前有效授权

通知列表、计数、已读和删除先核对实际收件人，再按消息所属工作角色读取授权。新版授权关闭组织基础能力后，列表和计数同步隐藏受限记录，相关操作也不能写入。有效的独立角色授权仍可在指定范围内生效，失效的分配来源不再影响结果。日程和审核通知继续复核各自关联记录的可读性。已有组织授权版本在能力或分配变更时更新，响应字段和缓存上限沿用现有约定。

## 统一授权接入（2026-11-01，开发中）

通知读取与删除在原收件人约束内叠加当前消息工作角色的统一规则，不开放他人的通知。列表和计数在同一读取事务内应用相同SQL范围后分页；已读使用读取范围，永久隐藏使用删除范围。批量结果重新计算未读数，不固定返回0。申请读取禁止同步隐藏申请通知；日程提醒经同角色的日程及来源参会名单判断，不再跨角色复用自然人级提醒结果。规则时间边界限制结果缓存寿命。其他领域通知和完整聚合角色行为仍需继续核对，本节不代表生产切换完成。

审核待办在原步骤资格匹配后，同时检查申请读取与处理能力。各工作角色独立计算；聚合使用当前账号有效会话和服务端角色目录，不能用客户端岗位或其他账号身份。拒绝后列表和数量共同移除，原详情及处理接口继续独立复核。规则起止时间进入缓存过期边界，授权事务更新的directory版本负责跨进程失效。当前只完成审核待办，其他领域待办仍需接入，不据此启用生产新模式。

## 2026-10-23 业务失效自动隐藏

列表、总数与未读数使用同一业务状态条件。审核只保留当前轮次最近已处理步骤的有效结果，后续处理、撤回和重提使旧进度消失；迟到或乱序投递不覆盖当前结果。场地通知匹配借用当前状态，人事审核匹配当前结果和处理时间，资料迁移要求仍存在对应结果，公示要求仍发布。日程提醒重新核对参会、实际时间、取消和结束，仅保留已到达的最近提醒；评分通知只在本人仍有未完成评分时保留，截止提醒替代开始提醒。

普通公告和账号安全告知仍按 30 天保留，不将读取当作已读或删除。自动隐藏不改写业务历史，也不替代自然人永久删除记录。前端已显示内容在下一次可见刷新时更新，离线画面不能即时撤回。

新类型必须登记 notificationLifecycle.policies；发件箱和最终写入拒绝未登记类型。新增业务类型需明确失效条件并测试列表/计数一致性、状态变化、乱序投递和组织隔离。消息缓存依赖 directory/notification/audit/venue/scoring/profile/calendar 版本；在线迁移 20261023120000_notification_lifecycle_versions.sql 增加目标索引与缺失触发器，不删除通知或业务记录。

接口均为已认证 POST `/api/<名称>`。目录只来自服务端认证账号的有效工作角色；`organizationId` 只缩小范围，不授予权限。响应保留原 `status/items/total/unreadCount/nextCursor/organizations/selectedOrganizationId/partial/failedOrganizations`。

| 接口 | 输入 | 行为 |
| --- | --- | --- |
| getMessageOverview | limit（默认 10）、可选 refresh | 兼容旧客户端，返回 todos 与 notifications 两组，仍须等待两组完成 |
| listTodos | organizationId、limit（1～50）、cursor、旧 offset、refresh | 返回去重待办，跨岗位选用原有优先级 |
| getTodoCount | organizationId、refresh | 相同资格/去重集合，只算数量，不格式化/排序 |
| listNotifications | organizationId、limit、cursor、refresh | 收件人去重，通知独立于待办加载 |
| getNotificationUnreadCount | organizationId、refresh | 计数 SQL，不读取通知列表 |

`refresh: true` 跳过结果缓存，不跳过认证、权限、限流、版本校验或并发控制；同范围在途计算仍可合并。缺省短缓存最多 5 秒，依赖版本变化立即换键。权限和资源执行再次读取权威事实。部分失败不存入正常缓存，失败组织仍明确返回，不伪装成空数据。

## 游标

新待办游标为版本 2，包含查询范围摘要、领域/列表版本摘要与排序位置。版本或范围不匹配、非法新游标返回 `status: cursor_expired` 和 locale 自然语言提示；客户端重读首屏。旧数字/base64 位移游标继续兼容。通知继续使用既有 createdAt＋id 游标。

游标不是授权令牌，不能凭游标读取其他组织。列表未变化不重新传入视图层、不清空已加载页数；数据确实变化时重建首屏并作废旧分页响应，禁止混合两个版本的列表。

## 客户端

2026-10-19 通知删除改为自然人级永久隐藏：deleteNotification仍接收id/organizationId，服务端通过认证角色目录核对收件权限，不接受客户端personId。notification_dismissals保存组织、自然人及业务事件摘要；删除不再物理移除投递回执。列表、总数、未读数共同排除该自然人已经删除的事件，同人其他岗位、管理身份及以后新岗位的同事件副本也不可见，其他人不受影响。事件归一化只移除已知收件身份结构，保留轮次、时间和内容指纹；无event_key的历史通知按原id隐藏，不能凭相同标题猜测为同一事件。已被旧版本物理删除且没有删除记录的历史动作无法追溯恢复。

删除记录不参与30天通知清理，原通知清理后重投也不会再次可见；删除事务内的触发器更新notification版本，两个API进程下次读取均使用新版本。deleteAllNotifications保留原组织筛选范围，对选中范围里的本人通知逐事件隐藏，不改变待办和业务状态。新建在线迁移20261019200000_notification_person_dismissals.sql；无需停机。

小程序删除成功重新读取权威列表，清理同事件的其他身份副本。网页补齐可见时30秒刷新、从后台返回刷新和离页清理；通知中心刷新已加载页数，内容不变不重置列表。其他设备已绘制的旧画面在下次读取/可见轮询时更新，不宣称离线设备能即时撤回画面。手机现场未验证，36项浏览器专项和隔离数据库真实HTTP删除回读通过。

- 门户与消息中心并行调用 listTodos/listNotifications；任一完成即可展示，失败仅影响本区，已有成功内容刷新时保持可见。
- `messageQueries` 合并相同范围请求、短期复用成功结果；业务成功/部分成功、退出、账号/角色切换立即清理。页面请求代次与会话快照共同阻止迟到写回。

## 2026-11-10：前端语料引用使用的消息事实

通知与待办新增 `displayFacts`，旧字段继续兼容；新版前端不得直接显示旧 `title/description` 中的系统句子。事实只包含已经获准读取的业务名称、姓名、时间与结构化状态，不包含学号、内部人员编号、投递键或岗位快照。数据库不新增历史事件，也不解析旧描述推测事实。

- 审核通知按精确事件键中的申请、轮次、步骤及类型查实际步骤和审批事件。`event.completedStepOrder/Name` 或 `event.rejectedStepOrder/Name/reason` 属于该事件，`current.status/stepOrder/stepName` 属于当前流程；终态不返回进行中步骤。事件无法证明时省略 `event`。现有事件未单独保存转交步骤，因此不返回 `event.nextStepOrder/Name`，也不从后续步骤或当前进度推测。
- 场地通知返回标题、场地名称和实际起止时间。本人当前岗位的借用沿用本人记录读取；经组织关联读取场地安排时同时校验场地、安排和借用读取能力，明确管理读取仍按该条资源判断。没有读取资格时通知仍可保留类型，但不附加业务详情。
- 资料审核通知仅为本人资料补充姓名和经核对的审核事件；迁移通知重新校验迁移读取权限，只返回来源、目标组织及 `current.status`，不把旧通知猜成迁移成功。评分待办提醒复用当前岗位的实际评分任务；公示通知还须命中同一有效岗位的公示查看规则。
- 日程提醒复用已核验当前参会权限的实例。`startTime/endTime` 是带时区的绝对时间；全天另有 `startDate/endDateInclusive`，结束日为包含的最后一天。系统内部日程时区单位为分钟。场地来源的历史时间待核对标志传递为 `startTimeReviewStatus/endTimeReviewStatus`。
- `deadline` 只表示当前评分配置计算的截止时刻；没有存储可信事件截止的历史通知不返回 `event.deadline`。四类待办分别补充当前步骤、姓名、时段或截止时间，保留原有平铺兼容字段。

列表分页后按领域批量读取事实，计数接口不执行这些详情查询。`notificationFacts.test.js` 覆盖事件与当前状态分离、岗位关系、明确拒绝、字段时间标志、本人资料和迁移/公示权限；`notificationDismissalIntegration.test.js` 使用隔离数据库实际 HTTP 回读审核与日程事实，并核对全天含末日。此验证不是生产规模性能结果，也不代表手机现场验收。
