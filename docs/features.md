# WHUSU Smart Workspace 功能口径

本文件记录人事领域整改后的用户功能与跨模块行为。视觉细节以 `docs/ui-kit.md` 为准，领域关系以 `docs/architecture.md` 为准。

## 人事目录与岗位

- 管理端按自然人展示成员，一人一卡；详情中展示该成员在当前组织的 0..n 个岗位。
- 在职无岗位成员仍在目录中，显示中性“暂无岗位”状态，可以维护资料和账号联系信息，但不拥有岗位规则权限。
- 新建或编辑岗位依次选择岗位性质、部门、身份类别、可选职能组。系统自动生成岗位标签，不提供岗位名称输入框。
- 职能组随部门联动；选择不属于当前部门的职能组必须在前后端都被拒绝。
- 删除岗位只影响该岗位，不自动离任；“离开当前组织”停用成员关系及其全部岗位，保留自然人、账号和历史，并支持重新加入。

## 工作上下文切换

- 用户按组织和岗位切换工作上下文；前端唯一当前键是 `activeContextId`。
- 有岗位的上下文展示生成的岗位标签和岗位性质；无岗位成员上下文明确显示暂无岗位，不伪造岗位或默认部门。
- 切换上下文后，审核、场地和评分权限立即按当前岗位变化；旧请求、缓存和迟到响应不得覆盖新上下文。

## 资料维护与审核

- 个人资料页同时显示审核状态和完整度。待审状态不会因必填项尚未生效而消失。
- 人员维护者编辑已生效资料；资料审核员查看生效值/待审值对照卡，只能通过或填写原因驳回。
- 驳回原因必填并进入审核历史。导入、人工维护和审核通过使用同一全局生效值同步规则。
- 姓名/学号纠错先预览受影响组织、成员关系和账号；学号冲突必须进入显式自然人合并，不得直接覆盖或新建重复自然人。

## 账号治理

- 账号属于自然人并跨组织生效。成员卡只显示一个合并账号状态，详细设备和恢复信息位于成员详情。
- 只有 `auth.accounts.global_manage` 可以冻结、解绑或重置全局账号。普通组织管理员看不到高危按钮，只能联系全局账号治理者。
- 离开一个组织不冻结账号，也不影响该自然人在其他组织的成员关系和岗位。

## 审核审批

- 发起条件、候选人、指定审批人、待办和审批动作均按有效岗位计算，并在动作执行时按当前岗位复核。
- 跨组织待办可见，但用户必须切换到目标组织和满足规则的岗位才能处理。
- 发起与每一步处理保存不可变岗位/工作上下文快照；指定人员同时固化其岗位；历史始终显示当时岗位，缺失岗位快照时授权失败关闭。
- 无岗位成员不能发起或处理岗位规则驱动审核。

## 场地借用

- 申请人规则、审批候选、待办和审批动作与审核模块采用同一当前岗位模型。
- 审批历史从借用记录和审批快照实时匹配；一条借用只显示一条历史卡，详情显示本人处理步骤及后续进展。
- 无岗位成员可查看允许公开的场地和日程，但不能提交或处理岗位规则驱动借用。

## 考核评分

- 后台评分对象与记录按岗位建立，评分资格和动作只认当前岗位。
- 前端默认按自然人展示；仅当同一任务中同一自然人存在多个岗位记录时，追加部门、身份类别和职能组标签区分。
- 自评限制按自然人判断，切换岗位不能绕过；历史结果使用记录发生时岗位快照，禁止用当前资料回填缺失快照。

## 字典治理

- 部门、身份类别、职能组是岗位与业务规则共享字典；职能组必须属于岗位部门。
- 任一字典项被岗位、规则、快照或历史引用后，删除操作必须被阻止，并向管理员展示引用类别与数量。

## UI 与可操作性

- 人事标题、筛选、批量操作、岗位组和资料对照区至少有一层蓝色轻奢玻璃语义容器。
- 资料对照卡保持“字段名 → 当前生效值 → 待审核值”的阅读顺序；手机纵排，Pad 可双列。
- 长弹窗使用固定标题、可滚动正文和固定底部操作栏；高度由内容和视口共同决定，手机、Pad 竖屏、Pad 横屏均能滚动到底并操作保存/取消。
- 所有提示、标签、空状态、确认文案和错误反馈进入 locale，不在业务代码中保留用户可见常量。
