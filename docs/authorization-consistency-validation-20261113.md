# 权限一致性与界面第二轮验收

## 范围与独立复核

2026-11-13，主项目直接实施。前端设计、语言撰写、前端实施由三个独立 Agent 完成，最终设计和语言稿均放行。具体方案及语料见 `copy/authorization-consistency-context-20261113.md`、`copy/authorization-usability-copy-20261113-v2.md`。

区分业务使用、权限分配与他人权限查询。普通岗位获得有效分配资格即可使用相应入口；仅有业务使用权的管理员不能分配；有效角色均可查询本人。受托分配使用一项完整资格，继承对象、记录、资料项及期限，不合并不同资格扩大权限。授权身份明确区分已发布功能与草稿，发布及恢复检查全部关联授权。没有生产数据或数据库结构变更。

## 针对性检查

- 后端隔离 MySQL 与 Express HTTP 验证包括真实前端参数保存、数据库和管理接口回读、越权拒绝、撤权、事务不写、历史版本读取和恢复，退出码 0。另有 30 项政策与入口单元检查通过，详见 `authorization-consistency-backend-validation-20261113.md`。
- 前端原生页面与共享逻辑 29 项通过；Chrome 手机、Pad 竖屏、Pad 横屏共 63 项不同场景通过，最后候选数据修改后受限分配保存回读 3 项再次通过。视觉检查 87 项通过。
- 人员选择器底栏自身补齐两列布局，避免依赖业务页面的 button-row 样式。4 种宽度与 9 组调用样式共 36 组几何检查通过，人员选择模型检查通过。
- JS 语法、共享生成物与语言唯一来源、严格语料、UI、按钮、滚动、键盘、控件完整性、页面注册及兼容检查通过；网页构建通过。用户本轮选择只做针对性检查，未运行完整 CI。

## 微信实际操作

主项目在官方工具自动化端口 9431 中，使用只存在于内存的固定应答检查两种角色：仅本人查询、受限分配。未调用生产授权写接口，预览及保存请求被测试应答拦截。真实页面进入授权编辑，点击选择岗位、点选候选卡、点击确认后，草稿实际取得所选 assignmentId。本人查询页面只出现查询任务，不显示分配或他人查询入口。

测试注入最初保留了自动化执行环境的数组构造器，微信组件拒收，不能据此判定生产接口失败。补齐可选空字段后问题仍存在；进一步比对 Array 构造器证实跨环境原因。固定应答按真实 HTTP JSON 解析后，页面候选、组件候选、过滤结果均为 1，实际选择确认成功。未为该测试现象放宽生产组件类型检查。全部模拟应答已移除并回到真实门户。

真实编译曾发现循环节点直接使用 wx:else 的错误，已改为条件 block 包裹循环并增加模板回归。官方上传日志及最终源码验证单独核对，不以 CLI 退出码 0 或旧二维码替代成功结果。

最终源码官方预览在网络 TLS 失败后重试成功，日志为 `tmp/authorization-consistency-release-fourth.log`，结果为 `√ preview`，主包和全部 6 个分包总计 4,435,156 字节。最终结果文件为 `tmp/authorization-consistency-release.json`，二维码为同名前缀 PNG。此前失败日志保留，不计为通过。

## 验证边界

浏览器固定应答回读、隔离数据库保存、微信原生模拟器点击是三种不同证据。没有在生产创建测试权限；没有执行微信正式版发布。实体手机、Pad 竖屏及横屏未完成现场验证。生产提交、自动发布、迁移计划与进程健康在部署完成后单独记录。
