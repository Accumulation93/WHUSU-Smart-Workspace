# 系统权限架构词汇清单

核对日期：2026-10-31。本文件整理当前称呼，供用户决定如何改名；没有据此改变权限或业务规则。

## 一、实体层级

```text
自然人
├─ 全局账号
│  ├─ 口令认证／微信认证（登录方式）
│  └─ 会话（登录状态，激活一个工作角色）
├─ 组织成员关系（对应一个组织）
│  └─ 岗位（可有零个或多个）
│     ├─ 岗位性质
│     ├─ 部门
│     ├─ 身份类别
│     └─ 职能组（可选，隶属部门）
└─ 管理授权
   ├─ 超级管理员
   └─ 普通管理员（组织内授权）
      └─ 具体管理权限
```

这是实体关系，不是把所有词排列成权限高低。普通岗位和管理授权是两条分支；当前工作角色决定本次按哪条分支执行。

| 层级 | 当前用词 | 含义 | 内部名称（不应直接显示给用户） |
| --- | --- | --- | --- |
| 人 | 自然人 | 同一个真实的人，跨组织共用 | personId、persons |
| 登录 | 全局账号 | 自然人的登录账号，不属于单一组织 | accountId、accounts |
| 登录方式 | 口令认证、微信认证 | 同一账号的两种认证方式，不是两套业务身份 | authentication/session |
| 登录状态 | 会话 | 一次登录及其当前激活的工作角色 | session、contextId |
| 组织范围 | 组织 | 数据及多数业务授权的边界 | organizationId、org_id |
| 组织关系 | 组织成员、在职、已离开 | 人与组织的关系及状态，离开不等于删除账号 | membershipId、organization_memberships |
| 当前操作身份 | 工作角色 | 切换岗位或管理权限时使用的总称 | contextId、activeContextId |
| 普通业务角色 | 岗位 | 某成员的一项具体任职；一人可有多个 | assignmentId、membership_assignments |
| 岗位属性 | 岗位性质 | 本会岗位、学院对接岗位、其他岗位 | assignmentNature、assignment_kind |
| 岗位属性 | 部门 | 岗位所属部门 | departmentId |
| 岗位属性 | 身份类别 | 部门负责人、主席团成员等组织内分类 | identityCategoryId；旧表字段identity_id |
| 岗位属性 | 职能组、工作分工（职能组） | 部门下属的工作组，可不填写 | workGroupId |
| 岗位显示 | 岗位名称／岗位展示名 | 按“身份类别 · 部门 · 职能组”生成，不是自由命名 | assignmentLabel |
| 管理业务角色 | 管理权限／管理授权 | 人取得管理员资格的记录，与成员岗位分开 | adminGrantId、admin_grants |
| 管理级别 | 超级管理员、普通管理员 | 两种管理员级别；普通管理员需具体授权 | adminLevel：super_admin、admin |
| 功能范围 | 权限分组、管理权限项 | 哪个模块中的哪项管理操作获准执行 | permission group、permission key |

## 二、规则层级

| 层级 | 当前用词 | 作用 |
| --- | --- | --- |
| 授权对象 | 本人／自己、指定人员、指定范围 | 规则覆盖哪些人或岗位；不同业务支持的选项不同 |
| 人员范围 | 部门、身份类别、职能组、自己所在范围 | 动态匹配当前有效岗位；不能跨多个岗位拼凑条件 |
| 条件组合 | 条件、条件组、任意满足、同时满足 | 同类多选通常为任意一个，跨类别通常同时成立；以模块具体规则为准 |
| 业务责任 | 发起人、借用人、参会人、审批人、处理人、评分人 | 业务中的参与关系，本身不是管理员级别 |
| 流程结构 | 审核模板／审批流程、步骤、轮次、当前步骤 | 决定由谁按顺序执行什么，不授予系统管理权 |
| 数据范围 | 可见人员、可见岗位、可见列 | 通讯录等按人、岗位和列裁剪数据，配置权不等于查看全部资料 |
| 执行权限 | 查看、创建、编辑、审批、导出、删除等 | 管理权限项或业务规则允许的具体动作；永久删除通常单独授权 |
| 历史事实 | 提交岗位、审批岗位、操作岗位、签署岗位 | 动作发生时保存的岗位信息；内部称不可变快照，不拿当前岗位覆盖 |

## 四、改名时需要特别区分

1. “身份”容易同时指自然人身份、身份类别、工作角色和管理员资格。当前统一切换入口应叫“工作角色”，具体任职叫“岗位”，岗位分类叫“身份类别”。
2. “管理权限”目前既用于切换到管理员这一类工作角色，也用于单个功能开关；这两层可以分别命名，避免混淆。
3. “审核流程”目前是模板管理的权限名，也出现在申请的流程详情标题；改名时应区分配置和查看进度。
4. “评分范围”与“删除评分类别”、“评分问题”与“删除评分模板”目前名称不成对。表中保留实际原名，没有假定它们已统一。
5. “工作分工（职能组）”与“职能组”是同一岗位属性的不同界面称呼，不是两个权限维度。
6. 修改显示名称可以保留接口和数据库标识；改变授权含义则需另行确认规则、兼容行为与验证范围。
