# 全系统统一日程：实施计划

状态：2026-10-19 两端页面、场地参会配置、订阅与一次添加已写入主项目；正在执行完整交付验证，尚未部署。生产及微信正式版状态另行记录，不以本地测试代替发布。

## 已确认的行为

- 小程序和网页同步提供独立日程子应用，月、周、日、列表视图，今天定位、日期跳转、搜索、来源筛选、全天/跨天、重复、提醒、参与人、修改与取消。
- 管理员按独立权限安排；普通用户默认只能安排自己，规则采用“授权给谁→可以安排谁→可以做什么”。同类条件OR、不同维度AND，必须匹配同一个有效岗位；多条件组OR。安排给自然人，同一人在多岗位、多设备只有一份参与关系。
- 场地借用审批通过后进入参会人日历；周期性活动按有效规则生成各次日程。场地调整、取消同步影响日程，原审批与历史记录保留。
- 合法安排直接加入，不设置接受/拒绝。普通参与者删除只退出自己，不影响其他人；场地参会名单同步去掉该人。安排者/有权限管理者取消整场须另行确认。
- 重复日程修改与退出提供仅本次、本次及以后、整个系列。范围成员动态更新，但主动退出记录优先，调岗或规则重新匹配不得自动加回；历史已发生实例不随当前成员关系改写。
- 手机日历支持则提供订阅，否则明确为一次添加；只显示已确认支持的入口，不把导入描述成持续同步。外部日历刷新由宿主控制。
- 日程这轮运行完整本机CI；通知删除为独立修复，仍只做针对性检查。
- 不做主动报名和可加入列表，只由安排人加入参会者。所有参会人都可以查看同场参会人的姓名及岗位，不返回学号、联系方式或其他人事资料。
- 可配置动作采用安排、修改、取消三类；不出现加入申请、同意邀请或拒绝邀请。参与者退出自己与安排者取消整场是两个独立操作。

## 实现边界和复用

1. 日程为核心模块，不复制场地审批逻辑。内部来源适配接口统一返回稳定的系列/实例ID、标题、时间、地点、状态、参会人和来源入口，注册场地借用、周期活动和独立日程三种来源，预留后续工作安排；客户端不能伪造业务来源或绕过原审批。
2. 场地日程与参会名单共用同一份参与规则和退出记录，取消个人参与采用事务，不维护两套互相漂移的数据。只管理参会人不改变预订人、审批人或场地占用规则。没有参会人配置的旧借用不猜测参加人员。
3. 规则配置复用通讯录条件的语义和共享人员选择器，不直接扩大通讯录权限。新增日程管理、规则管理权限；配置权限不附带查看所有私人日程的权限。个人日程默认私有，管理员只管理授权组织范围内的组织日程。
4. 系列保存重复规则与时区，实例按查询窗口展开，有查询跨度、规则复杂度和次数上限；不预建无限未来实例。全天是日期区间，不按设备时区平移；普通时间按项目UTC/系统时区规范。编辑例外以原始发生日期定位，修改时间不产生重复实例。
5. 动态参会人按当前有效岗位匹配并按自然人去重，具体名单服务端授权裁剪。未来实例可变化，过去实例保留当时事实；本人退出使用自然人级、实例/起始日期/系列级记录。失效或空条件不变成全员。
6. 时间冲突提供提示，不自动拒绝个人重叠安排；场地冲突仍由原场地校验决定。提醒按自然人、日程实例、提前量去重，更新/取消后撤销未发提醒，过期或退出不发送。站内通知为基础渠道，系统日历提醒受用户授权和系统设置限制，不承诺后台强制响铃。

## 手机系统日历

- 微信官方addPhoneCalendar/addPhoneRepeatCalendar是添加能力，需要用户授权；不能据此宣称可读取、修改或删除已加入的系统事件。
- 提供个人专用、可撤销/重置的随机订阅地址，服务端只存摘要，不暴露账号令牌、学号或参会人目录。只输出本人当前获授权的日程，采用稳定UID、版本和取消/例外表达，按iCalendar格式转义及折行。
- 订阅是工作台向系统日历的单向只读同步。工作台退出参会会更新订阅源；在外部手机日历里隐藏/删除一个副本不构成工作台退出操作。一次添加后无法自动撤销时，明确提示需自行处理旧副本。
- 设备能力无法可靠确认时不凭操作系统名称假称支持；iOS订阅及微信一次添加分别核查，Android各日历应用与桌面微信未测部分明确记录。

## 界面

- 共享Hero、Blue Glass控件和标准加载提示；手机默认月视图+选中日列表，周/日时间轴可滚动，Pad按三档布局；不把表格缩小后硬塞手机。
- 日程卡突出时间、标题、地点和来源气泡，详情再显示说明、参与范围及授权名单。今日/当前时间/全天区/跨天延续标识明确。
- 创建编辑为独立页面，参与人和范围复用标准选择器，规则条件折叠并显示摘要；区分保存日程、退出自己、取消活动。重复范围选择有明确日期和影响说明。
- 日期、颜色和提醒不依赖颜色独自表达；支持长标题、键盘、空状态、加载失败和权限失效。系统日历导入导出走已有统一文件输出和设备能力接口。
