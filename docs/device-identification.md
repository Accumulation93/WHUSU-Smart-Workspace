# 登录设备展示与识别边界

更新日期：2026-09-11。本文描述设备展示，不定义新的登录条件。

## 问题与事实

此前登录流程已移除设备信息前置依赖，但没有接回登录后的可选采集链。新会话的设备列因此为空；前端又把安装标识是否存在误写成“无法识别的设备”。设备型号缺失和安装标识缺失不是同一件事。

设备资料只能用于本人或已授权管理员查看登录会话，不能用于认证、续期、人员判定、会话互斥或权限判断。微信与口令登录均不等待设备采集；同一账号可保留多个有效设备会话。

## 采集与上报

- `miniprogram/utils/deviceIdentity.js` 优先读取 `wx.getDeviceInfo()`。接口缺失、抛错或型号/平台缺失时，逐字段尝试 `wx.getSystemInfoSync()`；`unknown`、`N/A`、`null`、`undefined` 占位不视为有效型号。
- 仅保存微信实际返回的平台和型号，不根据屏幕宽度、像素比、姓名、学号、OpenID、IP 或其他硬件特征推测型号。
- `miniprogram/utils/deviceMetadataReport.js` 在登录后的门户、本人资料页安排延迟采集；等待 500 毫秒，不进入登录临界路径。成功上报同一令牌后冷却 60 秒，再次显示页面可重新补采；不是后台永久轮询。
- 上报只调用 `POST /api/auth/security/device`，携带已捕获的当前令牌及 `{ device: { id, persistent, platform, model } }`。原生请求超时为 5 秒，不经过自动认证、请求重放和登录跳转链。
- 页面隐藏或卸载清理计时器并中止在途请求；执行和成功回调均核对令牌，旧账号/岗位的迟到任务不得更新新会话界面。本人资料上报成功后重新读取账号设备资料。
- 采集失败、存储不可用、上报失败或 401 均不改变认证状态、不触发自动微信登录，也不阻断业务。后续页面显示可以再尝试，不能无限立即重试。

## 型号与安装标识必须分开

| 数据 | 含义 | 不能据此宣称 |
| --- | --- | --- |
| `model`、`platform` | 微信提供的可选展示信息 | 平台验证了真实硬件、准确商品名称或安全可信设备 |
| 本地 `authDeviceInstallId` | 当前小程序存储中的安装标识 | 硬件序列号、自然人身份或防复制认证凭据 |
| 服务端 `device_key_hash` | 对持久安装标识做用途分离的 HMAC 摘要 | 已读取设备型号、完成硬件认证 |

安装标识只有存储写入并回读一致才标记 `persistent: true`；无法持久化时仍可展示实际型号，但不报告同一安装。模拟器切换机型可以保持同一存储，因而安装标识不变而型号变化，这不是两台真实硬件的证明。客户端资料可被伪造，不能作为安全放行条件。

服务端使用现有 `auth_sessions.device_key_hash/device_platform/device_model`，不新增表或字段。`sessionDevice.updateCurrentSession` 只更新认证中间件给出的当前 `sessionId + accountId`，同时要求会话有效且未过期；不接受客户端选择其他会话或账号。已有安装摘要不可由另一个摘要替换；空型号不能覆盖此前已记录型号。存储清除后产生的新安装标识不会抢改旧摘要，也不会让现有登录失效。

历史会话不批量回填，不把当前手机型号复制给其他会话。历史型号未记录时明确显示“暂未获取设备型号”；不能要求用户反复登录来假装恢复历史事实。`current` 表示当前会话；安装摘要匹配才可辅助标记同一安装，二者不要与“型号已识别”混用。

## API 边界

请求必须为对象，`persistent` 为布尔值，`id/platform/model` 为字符串。长度上限分别为 128、24、96；持久标识还必须匹配 16–128 位字母、数字、下划线或连字符。模型层 SQL 使用参数化查询，当前会话之外的行不得改变。接口失败不准返回令牌、安装原值、人员资料或内部数据库错误。

## 微信能力边界

微信官方说明 `getDeviceInfo` 从基础库 2.20.1 提供；其型号字段明确允许新机型暂时返回 `unknown`，平台枚举包括 `ohos` 和 `ohos_pc`。因此应修复平台没有采集、没有回退或没有保存的问题，但不能承诺微信未提供的信息也能被准确读取。[微信官方 API 类型定义](https://raw.githubusercontent.com/wechat-miniprogram/api-typings/master/types/wx/lib.wx.api.d.ts) 的 `DeviceInfo` 与 `getDeviceInfo` 条目是本次核对依据。

用户看到的是微信提供的型号，不一定是市场商品名或用户给设备设置的昵称。缺失时如实说明，不维护未经验证的型号猜测表。开发者工具模拟结果不能代替鸿蒙、iOS 或 Android 真机事实。

## 验证与交付边界

独立回归命令：`node scripts/device-metadata-regression-test.js`。覆盖新旧 API、异常与占位回退、存储失败、同一安装模拟型号切换、登录后延迟、账号/角色变化、离页取消以及 401/网络失败不重放。

上述脚本是隔离模拟测试，不是生产回读或真机认证。服务端接口/模型测试、实际微信编译、手机及 Pad 真机读取、生产部署状态应由本次交付记录分别列明；未执行不得标为通过。任何设备相关修改都必须继续验证两种登录成功不依赖设备 API，并回归跨账号隔离和历史会话保留。
