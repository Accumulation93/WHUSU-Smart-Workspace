## 全仓复核索引

`node scripts/performance-audit.js --json` 输出运行时代码逐文件、逐候选行号清单；包含生产路由、Model、Service、Worker、页面、组件，不含依赖和语言资源。当前扫描 293 个 JS 文件、约 8.3 万行。该文本扫描不是调用图证明，不能把每个命中都报告为缺陷。

记号：C=岗位数，O=组织数，P=组织参与岗位数，A=答案数，T=去重待办数，R=规则数，S=已选项数，D=历史天数，W=查询窗口中的实际重复次数。

缓存命中后的待办不再查业务列表、重算资格或排序，直接对快照分页；为保证调用方隔离，当前仍需解析有上限的序列化快照，CPU 并非严格 O(页长)。这是明确的剩余成本，不将其描述为 O(1)。

## 缓存契约与失效矩阵

消息缓存为每 API 进程一份 `BoundedCache`：5 秒、LRU、最多 256 项，键＋缓冲区＋元信息计费预算 16 MiB、单项 1 MiB，超大项不保存。预算不等于整个进程 RSS。截止从**计算开始**计，评分系统日期边界、dueAt、通知 30 天保留边界只可缩短。

键包含协议版本、账号、完整可用角色/组织目录指纹（包含权限资料）、查询条件及领域版本。通知只依赖 directory/notification；待办依赖 directory/scoring/audit/venue/profile。异常、部分失败、权限失败不保存为空结果。版本不可读或触发器未就绪时不读旧缓存，实时计算最多 8 个、排队 64 个，超过上限明确失败。

| 领域版本 | 写入来源 | 影响 |
| --- | --- | --- |
| directory | 自然人、账号、组织、成员、岗位、管理员授权/覆盖、字典、系统配置 | 所有消息及评分共享缓存；全局实体使用 `*`，组织实体只影响所在组织 |
| scoring | 活动、规则、条款、模板/题目、答案、记录、公示与评优指定 | 评分待办、结果、公示 |
| audit | 申请与步骤状态 | 审核待办 |
| venue | 借用状态、规则、共享场地 | 场地待办；场地本身是全局资源故用 `*` |
| profile | 组织补充资料记录 | 资料审核待办 |
| notification | 通知新增、实际修改、删除，包含 Worker | 通知页、未读计数，不使评分结果失效 |

完整表/事件登记在 `server/src/core/models/cacheVersionContract.json`；由新迁移安装 AFTER INSERT/UPDATE/DELETE 触发器，在**原业务事务内**递增。回滚同时回滚版本。MySQL 外键级联不执行子表触发器，因此相关父表也登记。无 org_id 的题目/模板顺序通过父表取得组织；不能伪造不存在的列。

版本在计算之前捕获，旧计算只可写旧版本键，不能在完成时重新取新版本。MySQL 共享评分缓存采用同样机制；原显式删除只是加速回收，不是正确性唯一依据。授权、认证、业务操作、附件和验签从权威事实读取，缓存不是授权凭据。不得在消息/公示缓存存学号、令牌或完整人事资料。

变更依赖表、原生 SQL、Worker 或迁移时必须同步登记。触发器带来同组织版本行的事务锁和写放大，不能假称零成本；持续观察事务耗时、死锁与连接池等待，再决定是否拆细领域。禁止为回避锁而把版本更新移到提交后。

## 观测与复验

- `request.performance` 用 requestId 关联：认证阶段、请求体阶段、各类待办阶段、handler 到响应、序列化、SQL 次数/行数/累计时间、连接池累计等待、输入/输出字节、总时间。并行 SQL 的累计时间可能大于请求墙钟，不可相加当作串行耗时。日志不含 SQL 参数、响应正文或身份资料。
- 该日志无法直接测量请求进入 Express 之前的公网、Nginx 排队或前端渲染。历史 5～6 秒再次出现时，必须以同 requestId 对照客户端、代理和服务日志，不要由单次快请求推出全部根因。
- 客户端 `api.getMessageTimings()` 只在内存保留最近 64 条请求号、请求耗时、响应字节和 setData 回调耗时/字段数，不写存储、不主动上传、不保存内容。setData 实际字节量在专项测试/开发者工具 Profile 测量，运行中不为每次更新重复序列化整表；`bytes: null` 表示未测，不是零。
- 独立数据库测试：设置 `DEPLOY_TEST_DB_HOST/PORT/USER/PASSWORD`、`MYSQL_BIN`，执行 `node server/test/performanceCacheIntegration.test.js`。测试自行创建唯一库/账号并清理，禁止指向生产。
- 专项规模测试：额外设置 `PERF_BENCH=1`，`PERF_BENCH_ROWS=8000` 或 `16000`；输出真实执行计划与业务路由统计，不写业务数据到生产。
- 防回归：`node server/test/performanceAlgorithms.test.js`、`node scripts/message-performance-test.js`、`node scripts/performance-audit.js --strict`；再执行全部工程门禁。修改不可变历史解释时同时跑评分/审批/签名安全测试。
- 已覆盖缓存容量/LRU、同键合并、部分失败不保存、计算起点 TTL、事务回滚、组织失效隔离、两个独立 Node 进程读取提交后版本、通知批量幂等且重投不失效、旧版本晚写、日历闰年与世纪边界、答案增长和选择补丁增长。通知 Worker 的评分日期、截止提醒和维护窗口统一使用系统配置时区；期限函数覆盖 UTC−12/UTC/UTC+8/UTC+12 的跨日边界。
- 双 PM2 实际业务压力、权限撤销并发、手机/Pad/鸿蒙体验版与公网端到端百分位，不能用本地单进程测试替代；未完成的项必须在交付中明确标注。
