# 岗位性质管理入口修复

原先岗位性质管理页已注册，但只有组织间复制结果能产生导航目标，且该目标遗漏可信路由登记；人事管理页签与授权能力映射也没有岗位性质。岗位编辑器的“新增性质”只能新增，不能代替字典管理目录。

小程序和网页现在人事管理中与部门、身份类别、职能组同层显示“岗位性质”页签，页签入口打开已有独立管理页，复用其读取、编辑、删除与组织校验，不复制CRUD。只按当前工作角色明确获得的`hr.assignmentNatures.read`显示入口；单有创建权限、其他人事读取权限或旧模式不推导读取权。普通岗位通过原人事子应用的业务管理页签进入；管理员通过人事管理进入。补齐可信路由后，组织间复制的性质编辑目标也可进入。

`scripts/assignment-nature-entry-test.js`实际加载正式Behavior验证：仅性质读权即可显示人事页签，真正入口方法使用已登记可信路径，撤权或页面隐藏后不能继续跳转。测试还验证创建权和其他人事权限不会显示性质管理入口；已加入CI清单。

`web/tests/e2e/assignment-nature-entry.spec.js`使用隔离响应，实际点击人事管理入口，到达性质目录并读取1次；仅创建权时没有入口，读权页面没有保存按钮。Chrome电脑、手机、平板3档共6项通过；网页332模块构建通过。小程序39页注册和114份WXML模板复杂度检查通过，未放宽2375元素上限。

以上不包含生产写入，不修改服务端授权，不代替微信实体手机或Pad现场验证；最终官方编译与门户实际点击由本轮交付另外记录。

入口修复同步后官方预览成功：总包4,090,762字节，主包412,454；审核392,146、消息36,281、组织194,905、评分1,285,774、场地508,972、工作区1,260,230字节。新版门户引入共用授权库后，生成器把这两项留在主包，已将adminWorkbench源对已删除分包副本的2处引用改为canonical主包路径；484个JS兼容审计通过。
