# 2026-10-30 网页新增、编辑及详情窗口复查

本轮逐处阅读 Vue 入口、状态、控件事件和共享弹窗样式，手写修复 3 处问题。没有使用批量替换脚本；没有在生产创建测试记录。全部改动直接写入主项目。

## 已修复并重现的问题

| 位置 | 修改前的实际问题 | 修复与验证 |
| --- | --- | --- |
| `web/src/components/AdminAuditTemplatePanel.vue` 步骤编辑 | `UiSwitch` 返回 DOM Event，页面把整个事件写入 `allowApproverDesignation`。浏览器实际请求出现 `{isTrusted:true,_vts:…}`，不是布尔值。 | 逐处改为读取 `$event.target.checked`。浏览器打开步骤，启用、确认、保存、重新读取、重新编辑，再关闭并保存，分别断言请求和重开状态为 `true`、`false`。 |

| `web/src/components/AdminAuditStampPanel.vue` 编辑印章 | 点击长目录末项编辑只更新页首表单，仍停留在目录底部。18 枚印章时名称输入框可见比例为 0。 | 给页首实际编辑区添加引用，更新后滚动定位。浏览器点击第 18 枚印章后检查输入框可见且名称为第 18 枚。 |

以上 3 个新增测试均先针对修改前构建执行，全部按上述原因失败；最终针对修复后构建在手机、Pad 竖屏及宽屏 3 档执行，共 9 次通过。没有把检查不到错误当作成功保存。

## 共享小程序 WXSS 几何专项补充

主任务调整共享弹窗为内容驱动后，新增手写 `web/tests/e2e/native-dialog-natural-layout.spec.js`，直接读取当前 `miniprogram/app.wxss`。夹具只将 rpx 换算成当前宽度的 CSS px，将浏览器不认识的 `view/scroll-view` 设为块级，并启用浏览器滚动；没有覆盖外壳或正文高度，也没有缩小按钮来通过检查。

- 390×844、768×1024、1280×800 三档，普通 complex 与 grid 共 6 个场景：短表单、展开 30 个条件、滚动到末字段、点击保存、240 px 键盘让位、恢复与收起全部通过。
- 每个场景要求正文高度大于 32 px、关闭按钮位于 108 px 安全线以下、保存按钮完整位于键盘上方、正文不覆盖底栏；短正文与实际内容高度差小于 28 px，收起后恢复初始高度（误差小于 2 px）。末字段在键盘前后均另行测量矩形，顶部和底部必须完整位于正文内边框之间（1 px 容差），不是仅检查露出一部分。
- wide 与 viewport 专业工作区共 6 个场景：键盘显示后外壳高度减少 240 px，收起后恢复原高度（误差小于 2 px）。
- 专业工作区夹具不使用普通自然正文的 `ui-dialog-scroll--natural` 和 `ui-dialog-scroll-content`，保留专业正文结构。加强完整可见断言后，12 个场景全部通过，执行耗时 7.8 秒；新增测试文件 `node --check` 通过。

这是浏览器对共享样式的几何验证，不能证明微信原生 `scroll-view` 内部视口已经正确，不能代替微信模拟器或手机/Pad 的滚动与键盘现场验证。
