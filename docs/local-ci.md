# 本机优先验证与发布

2026-10-15 起，本设备推送 main 或 feature/audit 时优先完成本机 CI。GitHub 只核验本机签名证明，然后部署；没有有效证明、拉取请求或手动选择强制远端时，运行远端完整 CI。两种方式使用同一份 scripts/ci/checks.json 与 run.js，不删除已有测试。

## 日常使用

- 这台设备已通过 `node scripts/ci/local.js install` 安装仓库级 `.githooks/pre-push`。正常中文提交后运行 `git push origin main`，自动验证并发布证明，不必另外再跑整套 CI。
- 提前验证已提交版本：`node scripts/ci/local.js verify`。相同完整提交在 24 小时内可复用证明，推送不会重跑；改动提交、树或检查规则后必须重新验证。
- 明确改用远端：本次命令设置 `WHUSU_CI_MODE=remote` 后推送新提交。已有证明的版本要强制重测，在 GitHub Actions 的 quality-gates 中选择 Run workflow，保持 `force_remote=true`。取消选择只会采用仍有效的证明，否则仍运行远端验证。
- 本机失败会阻止推送；修复后正常重试。证明推送失败也会阻止分支推送。禁止使用 `--no-verify` 伪装本机验证完成；绕过 hook 的推送没有新证明，将走远端完整 CI。

## 本机环境

设备配置在当前用户目录 `.whusu-local-ci/device.json`，私钥单独存放，不能复制到仓库、日志或其他设备。仓库只保存公钥；撤销设备时移除 trusted-devices.json 中的对应公钥。Windows 安装脚本收紧目录 ACL，不读取硬件标识或保存电脑名称。

本机需要 Node/npm、Git Bash、PowerShell、Chrome 和独立测试 MySQL。当前测试端口为 3362；配置中的 dbPort 可以调整。数据库主机固定本机回环，测试使用临时数据库，生产数据不参与。CI 启动先验证数据库可连接，不能靠缺失环境变量跳过集成测试。

每次验证在系统临时目录新建独立 Git 克隆，只检出指定提交，用 npm ci 安装锁定依赖；用户未提交文件、环境文件及旧构建产物不进入检查。成功和失败目录均保留以便排错，人工清理时只移除明确的 whusu-ci-* 临时验证目录，不能递归删除项目或共享依赖。

## 证明与执行

Ed25519 证明包含完整提交 SHA、Git tree、检查规则摘要、设备公钥标识、成功状态和时间。Git notes 的 refs/notes/local-ci 保存证明；先推 notes 再推分支，因此不需要再提交一份报告改变被验证的 SHA。GitHub 缺少 notes、签名无效、设备未登记或超过 24 小时均回到远端验证。

本机和远端均运行全部语法、静态审计、脚本测试、小程序测试、服务端测试、依赖检查、网页构建、视觉取值和浏览器测试。浏览器使用 2 个进程，与代码检查并行；两组全部结束且成功才生成证明。原生微信真实编译及实体设备现场验证仍按改动范围执行并另行记录，不能由这份证明代替。

GitHub 的 validation-complete 必须确认本机证明有效且远端按设计跳过，或远端完整成功。失败、取消、缺失和非预期跳过都不能部署。生产机不再重复运行语法和单元测试，可通过 `WHUSU_DEPLOY_RECHECK=1` 按需复核；锁定依赖安装、网页产物构建、密钥与迁移检查、独立端口健康检查、滚动切换和自动回退保持执行。

本地验证与 Linux 运行环境不同；生产独立端口预检用于检查真实运行环境。修改原生依赖或系统相关实现时，应额外选择远端完整 CI。该版本不按文件路径省略业务测试，避免在尚未建立可靠依赖映射时漏测跨模块影响。
