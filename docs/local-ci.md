## 当前自动化

- 默认 git push 只提交远端并进入生产部署流程，不运行完整 CI；validation-source、audit-and-test、validation-complete 均跳过，release-ready 单独检查这是否为预期跳过，不伪装验证成功。
- 涉及后端时先询问用户。用户同意后，优先执行 node scripts/ci/local.js verify；同一提交的签名证明在 24 小时内复用。也可明确设置 WHUSU_CI_MODE=local 后推送，让钩子运行本机 CI。
- 远端完整 CI 只在用户同意后手动触发 workflow_dispatch，并勾选 run_ci；force_remote 控制是否忽略有效本机证明。默认 run_ci=false，不因证明缺失自动启动 CI。
- 用户未同意或明确不运行时，不调用完整 CI，不设置 WHUSU_CI_MODE=local。保留针对本轮改动的必要本地检查及生产迁移、密钥、健康检查。
- 已请求的 CI 失败必须停止部署，不能改成“不请求”来绕过失败。只有用户明确改变本轮决定后才可重新安排。

## 本机环境

设备配置在当前用户目录 `.whusu-local-ci/device.json`，私钥单独存放，不能复制到仓库、日志或其他设备。仓库只保存公钥；撤销设备时移除 trusted-devices.json 中的对应公钥。Windows 安装脚本收紧目录 ACL，不读取硬件标识或保存电脑名称。

本机需要 Node/npm、Git Bash、PowerShell、Chrome 和独立测试 MySQL。当前测试端口为 3362；配置中的 dbPort 可以调整。数据库主机固定本机回环，测试使用临时数据库，生产数据不参与。CI 启动先验证数据库可连接，不能靠缺失环境变量跳过集成测试。

每次验证在系统临时目录新建独立 Git 克隆，只检出指定提交，用 npm ci 安装锁定依赖；用户未提交文件、环境文件及旧构建产物不进入检查。成功和失败目录均保留以便排错，人工清理时只移除明确的 whusu-ci-* 临时验证目录，不能递归删除项目或共享依赖。

## 证明与执行

Ed25519 证明包含完整提交 SHA、Git tree、检查规则摘要、设备公钥标识、成功状态和时间。Git notes 的 refs/notes/local-ci 保存证明；先推 notes 再推分支，因此不需要再提交一份报告改变被验证的 SHA。仅在用户已请求 CI 时，GitHub 缺少 notes、签名无效、设备未登记或超过 24 小时才回到远端验证。

本机和远端均运行全部语法、静态审计、脚本测试、小程序测试、服务端测试、依赖检查、网页构建、视觉取值和浏览器测试。浏览器使用 2 个进程，与代码检查并行；两组全部结束且成功才生成证明。CI 自己启动并关闭严格端口的预览服务，视觉检查和浏览器只连接本轮构建；不依赖人工预先启动服务或复用其他项目。原生微信真实编译及实体设备现场验证仍按改动范围执行并另行记录，不能由这份证明代替。

已请求 CI 时，GitHub 的 validation-complete 必须确认本机证明有效且远端按设计跳过，或远端完整成功。失败、取消、缺失和非预期跳过都不能部署。生产机不再重复运行语法和单元测试，可通过 `WHUSU_DEPLOY_RECHECK=1` 按需复核；锁定依赖安装、网页产物构建、密钥与迁移检查、独立端口健康检查、滚动切换和自动回退保持执行。

本地验证与 Linux 运行环境不同；生产独立端口预检用于检查真实运行环境。修改原生依赖或系统相关实现时，应额外选择远端完整 CI。该版本不按文件路径省略业务测试，避免在尚未建立可靠依赖映射时漏测跨模块影响。
