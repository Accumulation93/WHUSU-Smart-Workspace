# 权限分配可用性场景与结构设计

本记录由独立前端逻辑设计 Agent 编写，只规定业务事实、用户任务和控件语义，不是可直接进入语言库的定稿。2026-11-13；状态：结构交付，待独立语言放行及实施验证。

## 一、已核实的问题

1. 原生门户 `portal.js` 的普通卡片集合没有授权入口，管理员权限刷新只在管理角色执行。网页 `PortalView.vue` 先由角色卡片集合筛选，随后只按治理能力显示权限入口。网页授权路由本身只有登录要求，没有额外管理员拦截。
2. 服务端 `authorizationManagement.js` 的 `createGuard.authorize`、`readManagement`、`readCandidates` 三处均拒绝非管理角色。有效业务委托不能越过这三处。因此修复必须包含后端，不能只加卡片。
3. `authorizationAccess.current` 只返回使用能力，没有返回当前角色是否具有有效分配委托。分配资格必须来自服务端当前角色的有效委托，不能由任意业务权限或客户端角色名推导。
4. `authorizationEditor.setDelegationRecipients` 强制用 `adminGrants`，`delegationRequest` 也只接受管理身份。后端把委托接收者包装为 `authorization.rules.read` 规则标准化；该能力为治理能力，普通岗位会被拒绝。应独立验证委托接收主体，不能取消所有治理能力的管理身份限制。
5. 主界面把委托藏在按规则查看下，把草稿功能集合称为身份，把选择人员按钮复用为查询按钮。用户需要先理解内部对象才能行动。方案实际只有功能集合，没有岗位、数据范围或期限；保存草稿不改变现有规则，发布才更新关联规则。

## 二、授权边界

| 当前工作角色 | 入口及任务 | 禁止推导 |
| --- | --- | --- |
| 超级管理员 | 分配、方案、查询、委托四个任务 | 仍检查组织、版本和引用 |
| 获有效委托的管理身份 | 委托范围内分配与方案；查询按原许可 | 不得转授委托，不得改自身管理授权 |
| 获有效业务委托的普通岗位 | 仅当前岗位、当前组织、委托期限及范围内分配 | 不产生系统治理权，不合并同人其他岗位，不可转授 |
| 只有业务使用权的普通岗位 | 保留业务入口，不出现可写分配入口 | 使用某功能不等于可以把功能授予别人 |
| 只获查询权的角色 | 查询界面，无编辑目录和写入按钮 | 查询权不等于分配权 |

普通岗位委托只允许业务能力，不应允许其为管理员分配治理能力。创建、修改、撤销委托仍只允许超级管理员。普通岗位不能通过选中本人岗位、覆盖本人所属条件群体或编辑既有规则改变自身权限；后端应核对变更前后主体是否匹配当前角色，而不是只比较 `adminGrantId`。撤销、到期、停职、切岗后入口与请求都必须失效。没有有效委托时不能为了显示入口自动创建任何授权。

## 三、批准的任务结构

主 Agent 已依据用户明确业务决定批准以下结构：保留“授权身份”，一个方案对应一种授权身份，独立于人事身份类别。主界面继续三个主任务：给岗位或管理身份分配授权身份、维护授权身份、查询实际权限。首页围绕“给谁分配什么身份”；复杂禁止、自定义规则和超级管理员维护分配负责人进入明确标识的高级管理区，不增加第四个平级页签。高级区必须有任务解释和可发现入口，不能只给一个没有语义的展开箭头。

分配页中，按岗位/管理身份汇总与按规则查看是两个明确视图，不再用“高级”称呼一个列表模式。动态条件人群、禁止规则和自定义权限必须在规则视图可找到。批量删除仅在规则视图显示，避免用户对着人员列表误以为删除的是人员。规则共享给多人时，在编辑前说明修改作用于整个规则，不能把单人卡入口伪装成单人修改。

没有已发布授权身份时，日常流程引导建立并发布授权身份；高级区仍保留直接选功能建立规则的现有能力。简单编辑使用授权身份；高级编辑可选择具体功能、禁止方向、条件人群、字段和期限，切换模式不得清空既有条件。语料保留授权身份术语并在创建页解释其功能集合含义，不能暗示创建人事身份类别或实际岗位。

本次两条链分开验证：A 是管理员为普通岗位分配授权身份，B 是获得有效委托的普通岗位为其他对象分配。A 的普通岗位候选并未整体缺失：`authorizationCandidates.read` 从当前组织有效岗位返回 `assignments`；超级管理员直接获得这些候选，受限分配者再按委托的目标主体过滤。页面也已有 assignments 选择入口，但错误复用查询动作文字。没有岗位、离职、岗位引用无效、身份性质不合格的记录不会出现，不能为补入口扩大候选。B 的硬拒绝位置见第一节。

## 四、逐控件场景交接

| 位置/现键 | 用户对象和触发 | 真实结果与限制 | 相邻控件及下一步 |
| --- | --- | --- | --- |
| 门户权限入口 | 当前角色取得服务端分配或查询资格 | 打开同一授权页；不是切换管理员身份 | 当前组织/工作角色摘要保持可见 |
| 主页 rules/createRule | 分配人员创建一条授权规则 | 进入新表单；此时没有权限变化 | 先选对象，再选功能和记录范围 |
| 主页 schemes/createScheme | 管理可复用功能集合 | 创建草稿，尚未授予任何人 | 保存后回列表，再发布才可供规则引用 |
| 主页 effective | 用户查看自己或被准许查看的其他角色 | 显示该岗位/管理身份实际结果 | 查询对象选择与回到本人分开 |
| 主页 delegations/createDelegation | 超管指定分配负责人 | 授予分配资格，不授予使用权 | 接收资格者与最终获授权者分两组选择 |
| 列表视图切换 advancedRules/rules | 同一批规则的两种展示 | 只改变展示，不改变权限或授权模式 | 搜索、批量操作位于同一卡片 |
| batchSelect/selectShown/clearSelection | 规则列表勾选规则 | 仅改变本地选择；全选仅当前展示项 | 明确已选规则数量；删除进入预览 |
| 规则 edit/copy/remove | 某一整条规则 | 修改原规则/复制新草稿/预览删除 | 删除前展示全部受影响对象；复制未保存不生效 |
| 方案 edit/publish | 指定方案草稿及已发布版本 | 编辑只改草稿；发布更新关联规则能力 | 发布先预览影响，不说只是保存名称 |
| 编辑 name | rule/scheme/delegation三种独立名称 | 标记规则、功能集合或分配资格记录 | 三种标签分键；方案示例不冒充岗位名称 |
| 编辑 inspectAssignment/inspectAdmin | 在授权对象区选择岗位或管理身份 | 写入subject，不是查询权限 | 改用独立选择动作语料，确认后写回 |
| 委托 delegateRecipients | 超管选择承担分配任务的岗位或管理身份 | 写入audience；一岗一卡/管理身份按真实主键 | 与delegationSubjects最终接收权限者区明确分离 |
| 编辑 useScheme/stepIdentity | 选择已发布的功能集合 | 填入固定已发布功能，字段/范围仍独立 | 可展开完整功能；直接选功能为另一方式 |
| 编辑 allow/deny | 规则方向 | 允许规则提供许可；禁止规则优先阻断 | 说明功能和字段到底允许还是禁止，不能同字共用 |
| 编辑 scopes/stepScope | 业务记录范围 | 控制能处理哪些记录，不是授权给谁 | 本人记录、组织记录、岗位范围；不支持项不展示 |
| 编辑 fields | 当前选择的功能涉及资料项 | null为全部兼容字段；空数组不是全部 | 依允许/禁止/委托分开说明 |
| 编辑 startsAt/endsAt | 生效起止时刻 | 使用系统时区；空值表示无该边界 | 非超管不能越过委托期限，不能暗中设无限期 |
| 编辑 enabled | 当前规则是否启用 | 保存后改变启用状态；不是全局授权开关 | 与允许/禁止不同维度 |
| previewChanges/confirmChanges/revise | 已完整填写后预览 | 预览不写入；确认才写入；返回可继续修改 | 先列对象/功能/范围/字段/期限及前后变化 |
| inspectAssignment/inspectAdmin/ownRole | 查询页选择被查询角色或本人 | 服务端限定候选，不读取无权人员 | 无候选不能伪装加载失败；加载失败可重试 |

## 五、UI Kit 实施要求

复用紧凑工作台 Hero、顶部统一分段导航、控制卡和独立操作行。手机一至两列操作，Pad 用受控 px 令牌；不得把四个长页签挤成竖排文字。人员选择复用 personnel-picker，一岗一卡，整卡再次点击取消，确认后回写。选择按钮和查询按钮分语义，主动作每区只保留一个；返回/取消为次级，删除为危险操作。只给真实点击表面反馈。搜索、清除和批量操作不可悬浮在透明背景上。页面级样式复用现有令牌，不扩改全局样式。

## 六、验证清单与未完成事项

必须验证普通岗位有业务使用权但无委托不可分配、有有效委托可从两端门户进入并合法保存回读、同人另一个岗位不可复用、委托撤销/到期失效、越对象/功能/字段/期限拒绝、普通岗位不能授予治理权、不能给自己改权、不能转授、其他组织引用拒绝。需覆盖旧管理员委托与只读查询，避免修复普通岗位后回归。

界面验收包括三个主要任务及高级管理入口、每种新增/编辑/预览/保存路径、空授权身份引导和高级区直接选功能、规则列表批量删除、超管选择岗位作为分配负责人、长姓名和长授权身份名、三档布局。当前记录仅源代码排查和设计，不声称接口保存、浏览器、微信编译或实体设备已通过。完整 CI 未因本设计自动获授权。
