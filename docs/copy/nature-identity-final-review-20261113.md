# 岗位性质关联：独立语言复审与补稿

语言角色：final_language_review。只评审与写稿，不修改语料库或业务代码。

## 放行与必须修正的情境

原稿的短按钮、状态与长说明标点合理，可沿用。`unavailableDetails` 已能解释权限隐藏，不必额外编造无权限人员的身份或记录名称；只在 hiddenCount 大于零时显示。

解除预览中 `audit_history` 实际承载进行中步骤，必须映射为 `affectedApprovals`，不能使用删除字典旧分类里的“审批历史”，也不能默认归为“规则”。`stamp_bindings` 对应 `affectedStamps`。两端映射须一致。

公示编辑同时有查看者/指定人和被查看者/被指定人两种主体，仅重复“岗位性质”会让用户分不清范围。每组性质应与对应身份控件在同一语义分区，性质标签先于身份。以下补稿放行供独立实施者接入，不增加新的业务含义。

| 建议键 | 定稿 | 使用情境 |
|---|---|---|
| resultViewerNatures | 查看者岗位性质 | 公示查看规则授权主体 |
| resultTargetNatures | 被查看者岗位性质 | 公示查看规则目标条款 |
| meritDesignatorNatures | 指定人岗位性质 | 评优指定规则授权主体 |
| meritTargetNatures | 被指定人岗位性质 | 评优指定规则目标条款 |
| hiddenDetailCount | 另有 {count} 项明细不在你的查看权限内。 | count 必须来自 hiddenCount；仅大于零时显示 |

## 预览结构限制

普通编辑和解除关联不能一直显示“合并后的岗位性质”。合并场景用原稿 mergedNatures，其他编辑场景用 applicableNatures。被移除性质和身份名称必须在解除确认中完整可见。

岗位明细必须先显示岗位性质，再显示身份/岗位信息；若姓名没有读取权限，不能用姓名空白替代完整可读岗位说明，也不能拼接猜测姓名。标题为空但其他岗位字段获授权时仍可展示这些字段；无授权字段只计入隐藏数量。

本次为源码与情境复审，不代表真实浏览器或手机渲染验收。实施接入后需检查四种公示主体标签、解除预览分类、隐藏明细数量以及合并/解除标题分别正确。

## 2026-11-13 接入后独立复审

已核对共享语料与两端实际模板，四个公示主体标签及隐藏明细数量句式与本稿一致。公示的性质条件先于身份条件；普通编辑与同名合并分别使用“适用岗位性质”和“合并后的岗位性质”。两端均将 `audit_history` 显示为“进行中的审批”、`stamp_bindings` 显示为“印章授权”，隐藏数量只在 `hiddenCount > 0` 时显示。上述情境语言放行。

小程序新 `identityManager` 已按岗位性质、岗位说明、记录标题的顺序展示获授权明细，允许标题为空时仍展示岗位字段，不拼造人员姓名。

复审时仍有两项接入差异，修正前不作完整放行：

1. 网页 `AdminDictionaryPanel.vue` 的明细仍只渲染 `detail.title`，缺少 `natureName` 和 `assignmentLabel`。需与小程序保持相同信息顺序。
2. 小程序 `identityBehavior.js` 将评分、公示、审核模板、场地、通讯录、日程及统一授权等分类统一回退成“规则”；网页已复用 `dictionaryUsageCategories` 的具体分类。小程序也应复用这些既有语料，保留前述审批与印章专用映射，避免不同卡片都叫“规则”而无法辨认。

本节仅记录源码、语料及使用情境复核；没有操作浏览器或实体设备，不代表布局、滚动及触控验收。

## 最终接入复核：语言放行

上述两项差异均已修正并重新读取源码确认。网页与小程序的岗位明细现在都按 `natureName → assignmentLabel → title` 展示，各字段为空时不生成空白说明。小程序已复用 `adminPersonnel.dictionaryUsageCategories`，评分、结果公示、审核模板、场地借用、通讯录、日程安排、日程记录及授权规则均使用现有明确分类；审批、印章和复制草稿保留专用映射，与网页一致。

本次范围内的四类公示主体、普通编辑与合并、解除关联分类、隐藏明细数量及岗位明细已通过独立语言与场景复核，可以放行实施。此结论不替代权限、数据正确性、真实渲染或实体设备验收，未新增或更改任何产品语料及业务代码。
