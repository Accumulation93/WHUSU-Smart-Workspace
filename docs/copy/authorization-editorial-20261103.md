# 权限与组织复制：独立语言审稿

作者：独立语言 Agent `/root/language_editor`。日期：2026-11-03。仅撰写本文，不实施代码。

## 结构审稿结论

**不批准按现有结构直接替换一个“可以做什么”标题后交付。** 身份模板、允许规则、禁止规则和委托范围用了同一标题，但行为相反或对象不同。必须拆分情境文案；无需推翻整个三页签框架。

必须完成以下结构调整，才批准接入本稿：

1. 编辑页在表单前明确正在“新建身份／编辑身份／分配身份／调整权限／设置分配权限”，不能只有“权限管理”。摘要标题不能沿用编辑指令。
2. 操作区依 `kind` 和允许／禁止状态显示对应标题和说明。禁止规则不得显示“该身份拥有的权限”或“允许使用的功能”。选择身份后锁定的操作区明确告诉用户为何不能修改。
3. 对象选择、数据范围、字段范围是三个独立分区。禁止规则和委托范围也分别说明对象；不能继续把所有数据范围说成“可管理”。“与当前岗位相同”须指出是获得授权者使用的岗位，不能误解为配置管理员本人。
4. 无已发布身份时提供“前往身份设置”实际入口，判断依据为已发布身份数量；只有草稿时明确需发布。无当前受影响岗位不等于规则没有变化，影响页不能以人数为零显示“权限条件没有变化”。
5. 组织复制详情的对应项必须同时标出“来源组织选项”和“本组织对应项”；现在只有名称和“请选择”，无法判断正在改谁。接收成功明确接下来核对，不表示配置已生效。

验收条件：分别进入身份、允许、禁止、委托四种编辑状态；不看代码能指出权限属于谁、限制哪些记录、保存是否立即生效；复制详情能指出哪一列是来源。若无法做到，实施者应交回语言 Agent 重新设计，不自行补一句话绕过。
