# 权限与组织复制：前端逻辑语境审查

日期：2026-11-03。角色：前端逻辑设计 Agent。本文提供事实与结构要求，不提供最终用户文案；语言 Agent 独立批准后才可实施。

## 核对来源与范围

已重点核对 `shared/authorizationEditor.js`、`shared/authorizationPresentation.js`、`web/src/views/admin/AuthorizationView.vue`、`AuthorizationEditorView.vue`、`OrganizationCopyView.vue`、原生 `authorizationEditor.wxml` 及继承上下文中的确认页和组织复制页面。未将只读文件检查当作两端现场验收；全系统其余模块目前仅做文件分区，尚未逐页面审阅。

## 场景与实际后果

| 场景 | 主体与对象 | 动作、结果、限制 | 下一步与结构要求 |
| --- | --- | --- | --- |
| 身份设置 | 管理者创建可复用的能力集合；不是人事身份类别 | 保存草稿不生效；发布更新关联规则；集合本身不指定人员 | 名称、能力集合、保存草稿；随后发布确认。标题必须明确是该身份包含的权限 |
| 普通分配 | 当前管理者选择指定岗位或管理身份 | 选已发布身份，加数据范围；只影响所选工作角色，不合并其他岗位 | 三段分配→确认变化→保存；不得把自然人卡片误称所有岗位授权 |
| 额外规则 | 当前管理者为指定/动态岗位定义允许或禁止 | 允许与禁止的方向相反；未选不等于禁止；停用不删除；期限可空 | 能力、记录范围、字段范围标题需随允许/禁止区分，或使用中性规则描述；禁止配“可以做什么” |
| 动态人群 | 一组岗位属性 | 同组不同维度同时满足，同类别多值任选；多组任选；同一岗位匹配 | 结构必须区分一组内部条件与多组关系，不能只在页首放一句总说明 |
| 数据范围 | 规则涉及的业务记录 | 本组织、本人、指定记录、岗位筛选按目录支持选择；并集范围不等于交集 | 与“授权对象”分区，明确筛的是记录不是受权人；相同岗位条件以使用权限者的当前岗位为参照 |
| 字段范围 | 所选能力支持的资料字段 | null代表全部可选字段；空数组不能当全部；可选字段为能力交集 | 不把范围内所有资料无限开放；无可细分字段时不要诱导用户寻找不存在的字段 |
| 分配委托 | 管理者授予另一管理员分配资格 | audience是分配者；envelope.subjects是可受权角色；能力/范围/字段/期限限制其可分配上限，不直接授予使用权 | 两个人群必须各自标题、说明、已选摘要；不能共用“授权给谁”；先说明这是分配权 |
| 实际权限 | 查询某工作角色 | 服务端结果含允许/禁止/范围/业务条件；管理员不能据通用授权代替指定审批人 | 结果与原因同区，不能把“有权限”当流程处理资格；无权查询他人时只展示自身 |
| 修改确认 | 管理者确认某项规则修改 | 使用版本检查并再次服务端校验；返回修改不写；确认保存才写 | 明确受影响对象；共用规则编辑会影响其他受权者；不能把零命中岗位一概说成设置没变化 |
| 发布与恢复 | 管理者发布身份新版本 | 恢复发布新版本，不覆盖旧事件、不恢复业务数据 | 展示关联受影响范围与前后变化；恢复、发布分开确认 |
| 撤销规则 | 管理者删除指定规则 | 其他规则保留；删禁止可能恢复原来被限制的权限 | 危险确认必须包含规则与结果方向，不能总说权限减少 |
| 撤销委托 | 管理者撤销分配资格 | 原已分配的授权继续存在 | 与撤销业务权限分开表达 |
| 分享配置 | 来源组织操作人向有权目标组织分享指定配置 | 不是复制账号/个人资料/历史；不打通两个组织的工作角色权限 | 显示来源配置名、接收组织；来源变化或撤回导致草稿不可继续复制 |
| 接收 | 目标组织操作人接收分享版本 | receive只创建待处理草稿，有requestId避免重复请求；不启用规则 | 草稿页解释需要把来源人员/分类映射到目标组织；不能提示复制完成 |
| 创建副本 | 目标组织确认所有引用与目标场地 | apply创建独立配置；字典/事由和规则结果不同；不是持续同步 | 根据kind给后续动作，不能总提示“去启用”；同名/失效关联不能模糊归为失败 |
| 启用 | 当前副本有activation且未启用 | 只适用于该类副本；共享场地时间规则影响该场地所有组织 | 确认显示目标场地与跨组织影响；其他类型不能显示无效启用按钮 |
| 撤销分享 | 来源组织撤销分享 | 已创建独立副本不受影响；未创建草稿不能继续 | 不说删除来源或撤销全部副本 |

## 必须先解决的结构问题

1. 编辑器 `ui.capabilities/scopes/fields` 跨身份、允许、禁止、委托共用。实施应由已有 kind/effect 选取独立语料键，并将具体规则摘要保持中性；由语言 Agent 决定最终语句，不用一个“可以”标题覆盖相反意义。
2. 当前权限预览以 `roleCount === 0` 显示 `noChange`。零命中工作角色不证明规则条件未改变；应拆出零受影响对象状态，不能靠文案让错误推论成立。
3. 当前原生确认页主要列前后能力/字段，网页额外渲染完整规则摘要。两端都应显示本次规则的效果、对象、数据范围、字段、期限；委托预览还须显示分配者和可分配对象两类摘要。该差异须先统一结构，语言不能掩盖缺失信息。
4. 编辑器页头始终只有权限管理，无法区分新建身份、分配权限、委托。保留共享 hero，增加与kind、是否编辑对应的任务标题/短说明，不新增门户或多层弹窗。
5. 初次分配无已发布身份时，现只有提示；首页判定 schemes.length，不等于存在已发布身份。必须基于已发布项决定引导，并提供对应身份设置入口。不能叫用户选择不存在的项。
6. 组织副本顶部保留来源、状态和后续动作；待核对与已创建/已启用分清。不要把停用副本、权限草稿和无需启用的字典归入同一种操作说明。

上述是局部视图结构修正，保持原路由、API、权限判断、数据语义和共享选择器。若进一步更换授权业务模型或写入时机，须先按 UI Kit Manager 更新架构/接口/页面模板并重新评审，不能用此次写作授权顺手修改。

## 实施验收

后端补充核实：`server/src/core/services/authorizationPolicy.js:199-205` 中禁止规则 fields 为 null 时禁止整个动作；指定字段时从可用字段中移除这些字段，请求包含被限制字段则本次请求被拒绝。禁止规则的字段区域不能使用允许查看/修改的肯定描述。第123-125行的 same 比较对象是使用权限者的当前有效岗位。第236行的委托字段是可分配字段的上限。`authorizationImpact.js` 投影还包含未来期限，不能将当前可执行情况与拟保存条件混为一谈。

覆盖身份草稿与发布、允许/禁止、停用、无命中对象、共享规则、多岗位、委托两个人群、字段空选择、跨组织映射、字典创建、规则停用、共享场地启用。两端分别核对标题与实际提交对象；确认取消不写、保存后回读、撤销禁止的结果方向。用户可见文本全部使用共享语料引用，禁止在Vue/WXML/JS中补解释。手机与Pad未现场检查须明确记录。
