# 全系统分钟时间与消息入口提示：独立语言稿

语言角色：`/root/message_time_language`。本稿只定义批准语料，不修改运行语料库或业务代码；由独立实施角色接入。用户在本轮将时间要求扩大到全系统，以下规则适用于两端用户可见时间及人类可读导出。

## 放行结论

语言放行。全系统统一使用 24 小时制和两位时分，去掉秒和毫秒。普通单个日期时间保留既有 `YYYY-MM-DD HH:mm` 形式；消息及时间范围使用中文年月日。同一天的时间范围只写一次日期；跨天保留两端完整日期，不省略年份或月份。时间范围内使用半角短横线，不加两侧空格。用户的全局扩展要求是去掉秒，不因此改动日期输入及解析格式。

这是展示规则，不修改原始时间、时间先后判断、数据库、接口、密码验证材料或证据文件。缺少可信时间仍使用原有“时间待核对”，不得替换为猜测日期。普通日期值不附加时刻，全天日程继续明确标注全天。

## 批准的时间语料

建议集中写入 `shared/locales/zh-CN/time.js`。变量由时间工具按系统配置时区产生；语料函数只负责排列，不能自行换算时区。

| 建议语料键 | 完整模板 | 变量与实例 |
|---|---|---|
| calendarDate | `{year}年{month}月{day}日` | 年为四位数，月日不补零：`2026年1月4日` |
| minuteTime | `{hour}:{minute}` | 时分均为两位数：`09:05` |
| minuteDateTime | `{date} {time}` | 日期与时间间一个空格，消息中文示例：`2026年11月14日 16:30`；其他单值保留原日期样式：`2026-11-14 16:30` |
| sameDayTimeRange | `{date} {startTime}-{endTime}` | `2026年11月14日 16:30-18:30` |
| dateTimeRange | `{startDateTime}-{endDateTime}` | `2026年11月14日 23:30-2026年11月15日 00:30` |
| dateRange | `{startDate} 至 {endDate}` | `2026年11月14日 至 2026年11月16日` |

时间、日期和范围均为信息值，不加句号。短标签仍复用已批准的“日程时间”“借用时间”“截止时间”“当前截止时间”“开始时间”“结束时间”，不增加“具体时间”等重复标签。

同日同分钟不捏造秒数，也不改变原始顺序；单个时刻正常显示。只有起点或终点时分别显示对应标签，不补造另一端。需要标注全天时复用 `messageFacts.allDayDate` 和 `messageFacts.allDayDateRange`，保持“（全天）”只出现一次。页面实时日期时间按同样分钟精度展示，不另加精确秒的副标题。已有短日期、日期输入及不包含时刻的日历格式不因本轮统一改成中文。

日期输入值、程序比较键、导入解析格式和机器可读证据不是本稿的中文展示值，不能直接复用中文格式。设计角色已指出 `splitSystemDateTime` 不能从中文展示文本反拆日期，须继续返回独立的 ISO 日期和时分字段。

## 无法打开详情的提示

复用 `messageFacts.notificationDetailUnavailable`，定稿不变：**这条通知暂时无法打开详情。**

该句为完整说明，保留句号。它只在用户点击实际缺少可用详情入口的通知后显示，不放在正常卡片正文、卡片底部、时间行或摘要内。没有事实依据时不得加“已删除”“没有权限”等原因，也不承诺刷新必然解决。

待办使用独立键 `messageFacts.todoDetailUnavailable`：**这项待办暂时无法打开详情。** 原有点击路径在 `canOpen === false` 时直接返回，没有向用户解释；本句仅补充该点击情境，不能套用“这条通知”指代待办。完整说明保留句号，两类均通过项目标准提示组件呈现，不用会截断长句的短 Toast。

有合法入口的通知照常打开；接口明确返回的权限、删除或网络错误继续使用对应已批准的前端语料，不能一概替换为这句话。缺少时间、步骤或其他业务事实的既有短状态保留，其含义不同于入口是否可用。示例数据不应伪装真实跳转，也不应为了演示而在每张卡片添加异常提示。

## 结构与复审要求

不需要新增卡片或控件。删除常驻入口错误行后，卡片仍按业务标题、状态、必要事实和生成时间阅读；业务名称及步骤名称不减少。真正不可用卡片仍须允许触发解释，不能通过完全禁用点击使用户无反馈。

实施后须复核两端同日、跨日、单端、全天和待核对示例，以及正常卡片不出现入口错误、点击不可用卡片出现一次说明。语言放行不代表编译、部署或实体设备验收通过；实际截图复审另记。

## 场地活动范围补充放行

已核对现有 `shared/locales/zh-CN/venueFacts.js` 的两个完整前缀，保留原有含义，不把原安排和周期有效期混为本次使用时间。新增以下动态语料，仅用于两端均完整的时间范围：

| 键 | 完整定稿 | 示例 |
|---|---|---|
| venueFacts.originalScheduleRange(range) | `原安排：{range}` | `原安排：2026年11月14日 16:30-18:30` |
| venueFacts.recurrenceValidityRange(range) | `重复活动有效期：{range}` | `重复活动有效期：2026年11月1日 00:00-2026年11月30日 23:59` |

`range` 是公共时间工具按本稿生成的完整范围，语料及页面不得重新拆分或重排。两条均为标签加信息值，不加句号。未知时间继续保留待核对标记；明确不限的起点或终点沿用原有双参数语料，不把“不限”交给日期解析，也不补造起止日期。此补充语言放行，由独立实施角色写入运行语料库。
