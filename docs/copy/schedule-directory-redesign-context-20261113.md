# 日程参会与通讯录权限界面重设计情境

本文件由独立前端逻辑设计角色编写，只定义任务流程及业务事实。用户明确要求重设计操作逻辑，不能以追加控件或增加说明段落替代。用户界面定稿由独立语言角色提供，实施角色不得自行创作。

## 核实的结构问题

1. `calendarReminders.js` 创建 `type=calendar_reminder`，但持久通知类别是 `system`；门户及消息中心类别资源将 `system` 显示为其他。提醒标题本身已有日程事实转换，问题在业务分类，不应把所有系统消息整体改名。
2. 原生 `calendarParticipants`、网页 `CalendarSourceParticipants` 以及日程详情均无名单折叠状态；参会者多时，名单占据整个详情。
3. `calendarConditions`/`CalendarConditions` 直接把条件数组当成界面：先一个没有明确对象的类型下拉，再删除和选人按钮，然后所有范围。新增默认制造空范围，没有解释这是一批参会来源还是安排权限对象。
4. 通讯录编辑器与规则列表同时显示，编辑区追加在长列表下；编辑器三大区和所有条件组同时展开。列表本身也重复所有组说明。上一轮改善了措辞，但没有消除同时阅读、配置多组权限的负担。
5. 多处辅助操作使用完整主操作尺寸。选项、展开入口、添加来源、移除组、保存没有明显层级，用户很难判断操作作用于局部草稿还是整条规则。

## 共同结构

采用现有组件内的摘要、局部编辑、保存流程，不引入新路由或持久化协议。折叠状态仅属于当前页面，不进入服务端参数。

- 页面或组件常态先呈现已有配置摘要；用户只展开需要修改的部分。
- 同一编辑区域只展开一组详细条件，其他组保持可读摘要。新增组后立即展开并定位该组，不要求用户自行寻找。
- 每条组摘要显示类型及实际选项；不能只展示数量或笼统的已配置。姓名或范围很多时可换行，不把详情中的姓名压成横向长按钮。
- 局部操作使用项目紧凑操作样式；整条记录仅保留一组取消、保存主操作。关闭局部编辑只收起草稿，不误说已经保存到服务器。
- 不采用强制下一步向导：用户可随时回到任意分区修改，不必重复走完整流程。
- 控件密度变化通过局部语义类与设备令牌实现，不能缩小共享人员选择器或随意减少触控高度。

## 日程详情与场地详情的参会人

参会区常态显示标题、真实人数和展开指示，不铺开完整名单。编辑资格仍只取服务端 `canEdit`，编辑为独立紧凑操作，点击不得同时折叠。点击摘要展开完整已授权名单，姓名保留现有人事/通讯录关联入口；再次点击收起。

加载、加载失败、无权限、暂无名单均显示在摘要附近，失败有原地重试；不能折叠掉错误后伪装零人。切换记录、日期或工作角色时重置展开状态；后台刷新同一记录不无故收起。折叠不影响已加载数据，也不触发写请求。

这项结构同时覆盖原生日程详情、网页日程详情，以及普通/管理场地借用和周期活动复用的参会组件。不得仅修场地组件而遗漏日程自身名单。

## 编辑参会人及通用日程条件组件

日程来源页面保留来源类型提示，但主要工作区只处理参会配置。现有目标数组的语义为多个来源的并集，不新增排除或手动报名机制。

1. 每个已有来源先显示摘要，明确区分自身、指定人员、岗位范围。新建空来源直接进入编辑，已保存来源默认收起。
2. 追加来源时明确选择指定人员或岗位范围；不再点击泛化添加后立即生成未知含义空范围。已有自身来源保留可编辑和删除路径，不凭空增加默认参会者。
3. 指定人员进入共享自然人选择器，确认后回到来源摘要；取消不修改。已选计数与姓名在正文，不拼进按钮名称。
4. 范围先选岗位性质，再选部门、身份类别和职能组；已选值摘要常驻，未展开维度不铺满选项。与安排者岗位相同的条件仅在允许情境显示，保留与具体值互斥的现有保存行为。
5. 同来源不同属性必须由同一个有效岗位同时满足；多个来源取并集。来源范围随人员变动更新，已退出人员不会因重算再次加入；不能把来源组数冒充真实参会人数。
6. 每组使用独立紧凑移除操作，条件变更只更新草稿。不能因收起或切换组清空条件；删除最后组的原有限制不擅自更改。
7. `audience=true` 用于日程安排权限配置，主体是获得安排资格的人，不是参会者；标题、摘要和添加动作必须由用途参数选择。不得统一替换成参会人文案破坏规则管理。

## 通讯录规则工作区

### 规则列表

控制卡只放新增与批量管理入口。常态卡片显示规则名称、启停状态，以及查看者、可查看对象、补充字段三项简短结果；不重复完整匹配说明。完整条件由明确展开入口查看。

批量操作只在批量管理模式显示，全选、清空和删除不占据常态首屏。规则选择事件与编辑、复制、启停、展开隔离；批量删除仍保留目标名称和数量确认，不删权限之外的规则。

### 编辑模式

进入新增、编辑或复制后隐藏列表及批量工具，只显示编辑工作区；取消恢复列表及原选中状态。复制依然只生成草稿，保存才创建。

顶部显示规则名称和启用状态，下面按 audience、targets、fields 三张摘要分区组织。编辑已有规则默认展示三项摘要，新建默认展开 audience；点击任一分区只展开该区，其他两区仍显示实际选择。

- audience：谁获得查看权。按自然人选择或按查看者当前岗位筛选，多组为并集。
- targets：上述查看者能看到谁。自身指每位查看者，不指配置管理员；岗位范围的相同维度相对于查看者当前岗位。
- fields：对本条规则覆盖的人员可见哪些补充资料。基本资料固定必显，空选表示仅基础资料，不是全部资料。

各分区内部同样采用组摘要与单组编辑。必要说明只在对应编辑情境出现，不在列表、分区摘要和组内重复三遍。保存前保留完整三项摘要供核对；保存失败保留草稿，定位有问题的区并展开。

## 实施及验证边界

不修改权限计算、组织隔离、参会自动更新、退出记录、同岗位匹配或保存协议。分类展示可按可信 `calendar_reminder` 类型派生为日程，兼容历史 `system` 记录，不依赖后端消息中文或标题猜测。

必须覆盖：两组范围之间切换不丢草稿；新增组自动进入可视区；人员选择取消与确认；已有规则编辑保存回读；复制未保存不产生记录；最后组保护；批量模式退出不删除；展开收起不触发保存；保存失败保留配置；角色切换不显示迟到结果。语言角色复审完整界面及折叠摘要，而非只看键值表。

手机、Pad 竖屏和横屏分别核对首屏任务、长姓名、多来源、末字段和主操作；实体设备未验证必须单列，不以浏览器或开发者工具代替。此前 UI Kit skill 旧版选择芯片及 Flex 弹窗规则与最新 AGENTS 冲突，执行最新整卡选择及三段网格规定。
