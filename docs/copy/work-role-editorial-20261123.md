# 工作角色用词与场景记录

工作角色是成员在组织中办理事项时所使用的具体角色。门户、人员选择、审批、场地、评分和规则配置按此用词。权限角色是授权中心分配的权限集合。身份类别和工作角色性质仍分别是筛选与配置字段。人事界面用「任职记录」称呼可新增、修改和查阅的人事记录。

| 场景 | 定稿示例 | 数据来源 |
| --- | --- | --- |
| 审核详情（含重提） | 提交人 张三。以『学术部 · 部员』提交 | 首次提交事件及其快照优先。缺少该事件的旧记录使用申请保存的提交信息。重提时间在流程记录中查看 |
| 场地申请列表 | 借用人 张三。以『学术部 · 部员』提交 | 借用人和申请保存的角色名称。匿名占用不显示人员资料 |
| 审核流程的已办步骤 | 以『学术部 · 部员』审批 | 对应审批事件或同一步骤保存的历史角色 |
| 审核待办的角色提示 | 可用『学术部 · 部员』处理 | 该事项已经核实的可办理角色 |
| 缺少提交角色的历史记录 | 未记录提交时的工作角色 | 申请存在且角色名称未保存 |
| 权限分配 | 选择要授权的工作角色，再分配权限角色并设置可操作的数据范围。 | 当前选择的授权对象及已发布的权限角色 |
| 按工作角色匹配条件 | 同组条件须由同一个工作角色同时满足。 | 规则按一条工作角色同时匹配部门、职能组与身份类别等条件 |

小程序与网页从 `shared/locales/zh-CN/` 使用同一套词表。动态句由词表接收已经核实的角色名称。管理员创建、匿名记录和草稿按各自界面条件显示。人事导入同时接受旧版表头「岗位性质」「岗位识别码」。已配置的字典值、历史业务记录与接口字段保留原值。

## 2026-11-24 界面复核

审核与场地、评分与组织管理分别由两个前端场景 Agent 逐页核对。独立语言 Agent 核准定稿，实施后复核了入口和显示条件。评分范围短标签由语言 Agent 针对 320px 网页实测问题再次定稿。

| 场景 | 定稿与显示条件 | 事实来源 |
| --- | --- | --- |
| 审核详情 | 已知编辑事件用「编辑申请」，未识别事件用「其他记录」。以实存序号显示审批步骤；仅有重提快照时显示「未记录提交时的工作角色」 | `auditUser.js` 的提交、重提和详情映射 |
| 审核材料 | 网页区分「签名人」「用章人」与「有文件签署记录」。小程序流程同样不为文件签署记录显示个人签名人。签署工作区帮助提到实际按钮「暂存并返回」 | `auditUser.js` 的材料分类与最终 PDF 处理 |
| 网页审核列表 | 业务失败显示读取失败提示，成功且结果为空时显示相应空态。全部已读只在接口成功后更新未读标记 | 审核列表和标记已读响应 |
| 场地审批 | 「暂无审批记录」用于审批历史，人员称「借用人」。自动通过保留时间及自动状态，隐藏人工审批人及其工作角色 | `venueUser.js`、`venueApprovalMultiFlow.js` 及其步骤快照 |
| 评分 | 「开放考核公示」说明保存后的结果查看和评优资格。「同部门」「同职能组」以查看者所用工作角色为准。同部门且双方都未设置职能组时，保留原结果查看规则 | `publications.js` 的结果查看与评优条件 |
| 日程、通讯录及补充资料 | 日程区分「谁可以安排日程」「可以为谁安排日程」。通讯录字段按匹配的联系人卡片展示。补充资料说明条件组匹配及只读模板限制 | 日程策略、通讯录策略与人事资料适用规则 |
| 身份卡 | 「允许生成核验码」和「允许公开核验」分别说明对新码及已生成核验码的影响。仅有可展示的码时显示有效期。匿名失败统一说「本次未能核实身份」 | `identityCardAuthorization.js` 及身份核验接口的有效状态 |
