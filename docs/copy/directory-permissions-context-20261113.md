# 通讯录权限配置情境与结构

设计角色负责事实和结构，不提供用户定稿。权限依据为 `server/src/core/services/contactDirectoryPolicy.js`；界面为 `ContactDirectoryAdmin.vue` 与共享 `contact-directory` 组件。

## 真实行为

- audience 决定查看权接收者。people 按自然人，scope 只核对查看者当前岗位。
- targets 决定可查看对象；self 指每位查看者本人，不是配置管理员本人。scope 逐个目标岗位判断。
- 两侧条件数组分别为 OR；每组性质、部门、身份类别、职能组为 AND，每个维度的多个值为 OR。全部维度必须在同一个岗位满足，不拼接多岗。
- sameNature/sameDepartment/sameIdentity/sameWorkGroup 分别与查看者当前岗位比较。该岗位对应属性缺失时不匹配。同维度相同条件与指定值互斥。
- fieldIds 仅决定补充资料列；空选仍能查看目标范围内姓名和岗位基础资料。
- 多条命中规则按每个目标人员及岗位合并字段，不将另一人员的字段授权扩散。管理规则不授予资料读取权。
- 停用只撤去本条规则产生的授权，其他规则仍可能允许相同访问。删除同理，不能声称所有查看权必然消失。
- 新范围先选择性质；旧无性质条件保留原义。编辑旧范围时明确选择并确认范围变化。

## 需要修正的结构

当前两侧机械复用 conditionHint/groupMatchHelp，缺少谁符合条件及获得什么权限的主语；编辑组缺少明确编号、下拉选择方式无独立标签；列表 people 仅显示人数，性质摘要没有维度标签；补充资料空选只显示零项。

1. 保留三分区，分别表达查看权接收人、可查看人员、可查看资料。独立说明，不重复整段通用逻辑。
2. 两侧分别定义组标题、添加/删除动作、人员选择器标题。每组先方式，再内容。
3. OR 说明放对应分区，scope 内才显示同岗位组合说明；指定人员及本人不展示不适用的岗位组合说明。
4. scope 顺序为性质、部门、身份类别、职能组。相同条件明确相对查看者当前岗位。
5. 摘要显示指定姓名及人数；范围展示带维度标签的值。长名单允许折叠，不改变候选或保存对象。
6. 基础信息说明常驻；补充字段可折叠，空选明确结果。只调整展示，不改变保存参数、权限判断或新增确认流程。

## 独立写作范围

语言角色须覆盖列表摘要、三分区标题及说明、两侧组标题和按钮、方式标签、self 与相同条件解释、基础和补充资料结果、启停和删除影响。语言稿单独放行后实施者写入 shared/locales/zh-CN/contactDirectory.js，再同步两端生成物。

## 本轮验证

两端使用同一批准语料，保存参数和服务端权限判断不变。通讯录浏览器专项三档共 15 项通过，最终补充资料标题调整后管理用例三档 3 项通过；网页构建、原生组件保存参数、政策测试和隔离数据库真实新增/编辑/复制、启停删除、逐列隐私、并发及回滚检查通过。严格用户文案、指导语和三端本地化检查均无硬编码问题，共享副本一致。全仓文案质量报告仍有存量提示，未将报告模式退出成功描述为全仓文案质量清零。

微信开发者工具最终官方 preview 返回成功并生成二维码，主包及六分包总计 4,386,154 字节，证据为 tmp/directory-copy-preview.log。实际界面检查新建、岗位范围、本人说明、既有规则编辑、四项已选资料保留、末字段及取消/保存完整、蓝色开关和取消返回；没有向生产保存测试规则。两张原生截图由独立语言 Agent 复审，见同目录语言稿。过程中清理过编译缓存，工具仍有 SDK 路由、同步网络及空属性警告，不宣称控制台零错误。
