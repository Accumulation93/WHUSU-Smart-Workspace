# 全系统语料独立写作与实施

2026-11-03 用户明确要求。适用于所有子应用、两端页面、共享组件及服务端返回的用户可见文字。语言质量不能以长度短、没有硬编码或测试通过代替。

## 三个独立职责

1. 前端逻辑设计 Agent：读取实际页面、调用和服务端条件，提交场景资料。每条语料交代用户、所在页面、操作对象、触发条件、真实结果、下一步及相邻控件；区分个人、岗位、管理身份、组织、历史事实。不撰写定稿。
2. 语言 Agent：依据场景资料独立写作。每条记录语料键、完整定稿、变量含义及示例、是否需要结构调整和放行状态。遇到结构无法清楚表达时退回设计，不能为了满足现有控件硬凑文字。实施 Agent 不能代替语言 Agent 签字放行。
3. 实施 Agent：只把已批准定稿接到批准的位置。发现语义、变量或布局不适配时退回前两方，不擅自缩写、拼接、改写或添加提示。实施后由语言 Agent 核对实际界面与定稿，前端 Agent 核对流程和布局。

三个职责由不同 Agent 承担；可按模块连续协作，但不能由同一个 Agent 换角色完成同一模块的写作和实施。主 Agent 负责范围、工程引用和验证汇总，不绕过独立写作。上下文恢复后依靠记录继续，不能把旧实现者写的文案直接标成独立审稿。

## 覆盖与事实边界

标题、页签、按钮、字段、输入说明、选项、空态、加载、成功、错误、确认、通知、辅助说明、无障碍标签、文件名模板、导出表头、报告、动态格式化函数均纳入。标准名称仍由语言 Agent 审阅，可以保留同值，须有明确理由；不能为了显得“重写”改变业务术语。

人员姓名、用户填写的标题或表单、历史签署文件、业务事实及第三方原文不是系统提示语，不批量改写。内部路由、能力键、状态枚举、SQL、日志和错误码不作为用户文案重命名；若直接展示内部内容，则先调整展示来源，保留机器协议。没有核实的状态不得通过措辞包装为成功。

## 独立语料及稳定引用

- 唯一运行语料源为 `shared/locales/zh-CN/**`，包括该目录内的历史 `generated` 源。业务代码只引用语义键并传变量；不得保存用户提示字面量，不得在 JSX/Vue/WXML/CSS、服务端返回或配置中复制另一份。
- 两端及服务端副本继续使用现有生成链，禁止手改副本。写作稿和情境记录在 `docs/copy/`，属于编辑依据，不是另一套运行文案来源。
- 一条完整动态句子由语料模板或函数拥有；业务代码不拼词造句。同字不同含义必须分键，同义且相同上下文才复用。生成器不得仅因文案相同而改绑另一模块的键；失效引用必须报错，不能猜测替代。
- 新文案及场景变化须重走三方流程。未经语言 Agent 复核的结构重排不能直接套用旧提示。
- 网页别名新增或纠正引用在 `scripts/locale-reference-bindings.json` 手工登记模块及键路径，再由 `locale-align.js --write` 生成。未登记修改保留既有显式引用；既有引用是否语义正确仍须逐模块审阅，稳定引用并不等于存量全部正确。`locale-reference-test.js` 检查同值不串线、改稿保持键及失效引用阻断。

## 结构改造

遵循 UI Kit Manager：先记录页面/模块、现有组件、数据/API、权限及引用影响，再实施已获授权的改造。优先复用共享组件、标准加载、人员选择、标题和间距令牌。语义分区或显示逻辑调整不修改业务权限、历史数据和保存含义；发现需要改变这些行为时单独确认业务方案。两端结构同步；不能把结构问题掩盖成更长说明。

## 完成记录

全量盘点见 `corpus-inventory-20261103.md`。按模块逐键记录：未审阅 → 场景核实 → 语言放行（或结构退回）→ 实施 → 引用/参数验证 → 实际界面复核。计数要区分唯一条目、聚合重复、两端副本和运行时业务数据。部分通过不能宣称全系统完成。

验证包括共享源一致性、稳定引用、格式化参数、失败与成功分支、保存后回读、长值与三档布局、微信真实编译和可执行的现场检查。源码审计只能查分离与引用，不能自动判断自然语言合格。不可运行的实体设备明确记录。CI 是否运行、提交及发布仍遵守 AGENTS.md，不自动扩大为全量 CI。
