# UI Kit 硬规范

项目 UI 事实来源为 `docs/ui-kit.md`、`docs/ui-components.md` 和
`docs/ui-page-templates.md`。本文件记录一旦破坏就会造成真实业务错位的硬契约。

## 间距所有权契约（不可破坏）

1. 每段可见空白只允许一个几何所有者。页面四边归 `.page`，玻璃卡内容边缘归卡片 padding，字段间距归字段父级或统一相邻项规则，标签到控件归标签规则，正文到操作区归 `.ui-dialog-footer`。禁止父级 padding、子级 margin、空白占位节点为同一段距离重复叠加。
2. 运行时统一使用 `--ui-field-gap`、`--ui-label-gap`、`--ui-inline-gap`、`--ui-action-gap`、`--ui-control-padding-*`、`--ui-compact-padding-*`。手机、Pad 竖屏、Pad 横屏分别取 `app.wxss` 的设备值；页面级样式只能表达业务布局，不能重新猜测基础间距。
3. 普通页面底部必须保留 `--ui-page-padding-bottom + safe-area-inset-bottom`，页面级禁止固定 `padding-bottom` 覆盖安全区。内容必须自然撑开，禁止普通卡片固定视口高度或添加大块尾部 padding；专业时间表、虚拟键盘等覆盖型工作区的例外必须局部命名并写明原因。
4. 创建/编辑弹窗采用“标题 / 可滚动正文 / 独立操作区”。提交、保存、取消按钮放在滚动正文之外的直接子级 `.ui-dialog-footer`；正文不得用底部 padding 为按钮占位，按钮不得用 margin 调整上下距离。正文到按钮由 `--ui-action-gap` 控制，按钮到底边由弹窗外壳 padding 控制。
5. 控件使用 `min-height + 对称 padding + 语义 line-height`，禁止固定 height、固定 line-height、上下 padding 三者叠加。文字到边缘必须由控件 padding 产生，长文字自然换行并增高，不能裁切或靠空格对齐。
6. 每次间距修改必须人工阅读相邻 WXML/WXSS，分别核对首项、末项、空状态、长文案、滚动到底和底部安全区，并在手机、Pad 竖屏、Pad 横屏现场查看。脚本扫描只能作为候选定位和最终门禁，不能代替逐项语义判断。

## 控制表面与卡片操作契约（不可破坏）

1. 页面级 `section-title`、分区二级页签和成组操作必须拥有至少一层真实可见的玻璃表面；`.page`、`.admin-workbench`、`.section-stack`、`.ui-dialog-stack` 等透明布局层不算视觉包裹。禁止标题、页签或按钮组零容器直接暴露。
2. 同一分区的标题、页签和批量操作使用 `.section-control-card` 共同承载。不得为了形式给每个控件重复套同质卡片，也不得因增加表面改变原有滚动所有者。
3. 重复列表卡片的小型查看、编辑、删除、移除操作统一使用 `.card-actions`：默认独立成行、顶部细分隔、右对齐、允许换行；操作控件最小宽度使用 `--ui-card-action-min-width`，间距使用 `--ui-card-action-gap`，圆角使用 `--ui-control-radius`。危险操作保留红色语义。
4. `.card-actions--inline` 只用于已经证明不会与标题、状态、展开入口争抢空间的紧凑行。展开卡片的操作必须处于普通文档流，禁止 `position:absolute`、固定 `top/right`、负 margin 或覆盖层定位。
5. 审核模板卡固定按“摘要与展开入口 → 编辑/删除操作行 → 展开步骤内容”排序；编辑、删除不得与展开按钮同一绝对定位区。
6. `scripts/ui-audit.js --strict` 必须检查裸露标题/分区控件和遗留卡片操作组。修改后在手机、Pad 竖屏、Pad 横屏核对长文案、操作换行、收起和展开状态。
7. 同一视觉行中的日期/时间选择器、筛选按钮、清除/重置按钮使用 `.ui-inline-control-row` + `.ui-inline-control`，高度只能来自 `--ui-inline-control-height`；带标签的并列筛选字段使用 `.ui-inline-field-row` 对齐字段底边，并统一内部 `.compact-picker-value` / `.field-input` 的最终高度。原生 `input` 必须保持 `display:block`。所有子项上下 margin 必须归零，必须审计最终级联样式，防止共享 `.filter-clear` 等同名规则重新加入 margin。
8. 标题旁的宫格/列表等二态切换使用 `.ui-compact-segmented` + `.ui-compact-segmented-item`，高度来自 `--ui-compact-height`，不得进入整行主页签的均分、宽度或 `--ui-tab-min-height` 规则。

## 卡片式选择器契约（不可破坏）

1. 卡片选择器使用 `.selection-option-card`，一张卡只表示一个可选业务单元。人员按岗位选择时，最小单元固定为“人员 · 岗位”，同一自然人的不同岗位拆成不同卡，不能在一张人员卡内再让岗位信息气泡承担选择。
2. `.select-chip.selection-card-toggle` 必须是卡片的第一个可见子项，位于左上起始位且不收缩；未选文案为“选择”，选中文案为绿色“取消”。已选区与候选区必须使用相同位置和语义，禁止另设整行“移除”操作。
3. 姓名、学号、岗位性质、部门、身份类别、职能组、岗位标签与状态标签均为只读信息。禁止在这些文本或气泡上绑定选择事件，禁止写成“已选 · 身份类别 · 部门”，也禁止把选择控件塞进 `.list-name`。
4. 选择卡正文必须 `flex:1; min-width:0`；左上选择控件必须 `flex:none`。`.card-actions`、`width:100%` 操作条或绝对定位操作不得进入卡片媒体行，以免把姓名、岗位标签挤成逐字纵列。
5. 修改后必须全仓审计所有卡片式选择器，并在手机、Pad 竖屏、Pad 横屏检查未选/已选、长姓名、多岗位、滚动到底以及选择—取消往返。严格 UI 审计必须阻止上述结构回退。
6. 人员按岗位选择时，选中键固定为 `assignmentId`，部门/身份类别/职能组条件必须由同一岗位元组满足。账号治理、认证授权等明确按自然人授权的选择器可以使用人员 ID，但必须在业务说明和代码命名中标明该例外。
7. 单击即导航、选择后立即关闭的单选卡不属于可逆卡片选择器，可省略选择/取消控件；不得因此把“已选”塞进信息气泡。兼具编辑/删除的规则卡把选择摘要作为 `.selection-option-card`，其他操作放在摘要之外。

## 媒体行、消息元数据与品牌页脚契约（不可破坏）

1. 左图标媒体行固定为“受控图标槽 + `min-width:0` 正文 + 固定尾部操作”。多行卡片必须顶部对齐，图标不可相对整张卡片垂直居中。
2. `ui-icon` 的业务级图标必须使用 `sizeRole` 语义尺寸；手机、Pad 竖屏、Pad 横屏分别由组件给出 `rpx/px/px` 尺寸。固定 px 外框内禁止继续放随视口增长的 rpx 图标，图标本体必须有 `max-width/max-height:100%` 防溢出。
3. 门户和消息中心的类别、组织、岗位禁止混在一个自由换行容器。类别与岗位处于明确上下文行；组织与当前标识独占完整下一行，名称 `flex:1; min-width:0`，当前标识不收缩且不换行。空间不足时名称只在该语义行内按词自然换行，禁止截断完整名称或拆字挤成碎行。
4. 页面底部主操作间距使用 `--ui-page-action-gap`，品牌页脚上间距使用 `--ui-footer-gap`。操作组与品牌区由同一语义容器管理；页面 Grid、相邻卡片或页脚局部规则不得把专用间距清零，也不得以 `--ui-inline-gap` 替代。
5. 修改后必须现场检查手机、Pad 竖屏、Pad 横屏的门户预览和消息中心，并全局复核共享 Hero、列表入口和固定 px 图标槽；严格 UI 审计必须拦截组件回退到无条件 rpx、消息元数据回退到 `flex-wrap`、操作组复用行内间距和页脚失去专用间距。

## 人事领域与工作上下文契约（不可破坏）

1. 实体层级固定为“自然人 → 组织成员关系 → 岗位”，全局账号挂在自然人上。岗位由岗位性质、部门、身份类别和可选职能组组成；禁止自由文本岗位名称，展示名统一由“身份类别 · 部门 · 职能组”生成。职能组非空时必须与岗位部门一致。
2. 名称必须无歧义：`contextId`/`activeContextId` 是工作上下文，`assignmentId` 是岗位，`identityCategoryId/Name` 是身份类别。界面中的“身份类别”只表示组织字典，不得把工作上下文或岗位简称为“身份”。
3. 一名自然人在成员列表只出现一张卡；岗位只在成员详情分组展示。成员资料目录必须合并在职与已离开成员，默认显示全部，禁止建立独立“已离开成员”页签、列表或第二套人员目录。无岗位在职成员使用中性气泡；已离开成员使用灰蓝气泡并在只读详情展示离任时间和离任前岗位，不显示虚构的默认部门、身份类别或职能组。
4. 审核、场地和评分的规则驱动动作只按当前岗位授权。无岗位成员仍可维护个人资料和查看组织公共内容，但不能发起或执行岗位规则驱动动作。指定自然人时必须同时指定其岗位；历史必须展示操作发生时的不可变岗位/上下文快照，缺失快照不得以当前资料猜测授权。
5. 资料界面同时展示审核状态和完整度；存在待审提交时不得因资料不完整显示为未提交。人员维护者编辑生效值，资料审核员只比较和审核待审值；对照使用生效值/待审值比较卡，驳回弹窗必须采集原因。
6. “离开当前组织”、永久删除当前组织成员记录、彻底删除自然人和删除账号严格分离。离任同步撤销当前组织普通管理员授权、权限覆盖和管理员上下文会话，但不得修改全局超级管理员治理权。永久删除必须先做全引用预检：业务事实作为阻断项，允许清理的未执行引用作为自动清理项；清理后零候选的模板、步骤或规则必须停用并返回待修复清单，不得扩大候选。组织删除不得影响其他组织或全局账号；彻底删除仅限超级管理员并要求输入学号二次确认。组织成员删除也可能移除管理员授权，必须与自然人删除共用全局治理锁，并在事务内复核最后有效超级管理员，禁止只在彻底删除自然人时保护。账号高危操作只对具备 `auth.accounts.global_manage` 的用户显示；其他组织管理员只显示合并账号状态和联系全局管理员提示。
7. 部门、身份类别、职能组一旦被任何岗位、规则、快照或历史引用，删除入口必须被阻止并展示引用分类/数量；不得提供自动替换、级联删除或停用绕过。
8. 成员目录的查询字段、关键词、排序、高级筛选和批量工具必须共同位于一张 `.section-control-card`，高级筛选在卡内展开，不创建嵌套窗口。已选条件使用紧凑气泡，可单项清除和全部重置；手机单列/双列组合，Pad 使用紧凑网格。资料对照卡先显示字段名，再并列/分栏展示“当前生效”和“待审核”；手机可纵向，Pad 可双列，但信息顺序一致。
9. 人事长弹窗统一“固定标题 + 直接子级 `scroll-view.ui-dialog-body` + 固定 `.ui-dialog-footer`”。高度由内容和视口共同决定，正文溢出后内部滚动；不得固定正文高度或把保存按钮放进滚动区，三档设备必须验收滚动到底、错误提示和操作可达。
10. 人员筛选必须在完整目录上本地执行。同类多选按 OR、不同类别按 AND；岗位性质、部门、身份类别和职能组必须由同一条岗位元组同时满足，禁止跨两个岗位拼接命中。已离开成员仅以离任前岗位参与匹配并明确标注历史岗位。批量选择和导出只作用于当前可见且有权限的结果。
11. 已离开成员的详情除“重新加入”外全部只读；重新加入只恢复在职无岗位状态。永久删除入口只能位于成员详情的危险操作区，使用红色语义，并通过固定标题、滚动预检正文和固定操作栏展示阻断项、自动清理项及待修复规则。

## 绝对时间、日期型值与视图契约（不可破坏）

1. 绝对时间在数据库中统一以 UTC `DATETIME(3)` 保存，服务端统一返回 ISO UTC。`system_config.timezone` 只表示系统显示时区偏移，不得改变数据库存储时区；小程序按 `systemTimezoneOffset` 和配置版本换算，禁止依赖设备本地时区。
2. 纯日期 `YYYY-MM-DD`、每日时刻 `HH:mm`、时长、提前量和周期规则属于日期型/规则型值，不是绝对时间；它们保持业务原值，禁止套用时区转换。新增字段、接口和 locale 文案必须明确所属类型。
3. 列表时间统一预计算为 `YYYY-MM-DD HH:mm`；详情、验签和安全记录统一预计算为 `YYYY-MM-DD HH:mm:ss`。视图层只渲染 `createdAtText`、`processedAtText` 等展示字段，禁止直接绑定 `createdAt/updatedAt/processedAt/signedAt/expiresAt` 等原始字段或显示 ISO `T...Z`。
4. 页面不得自行使用 `toLocaleString`、`toLocaleDateString` 或设备 `Date` getter 生成用户时间；系统设置变更后必须刷新全局时区缓存并重算当前页面展示字段。
5. 历史迁移必须按写入来源分类：数据库 `NOW()/CURRENT_TIMESTAMP` 形成的本地墙上时间与代码明确写入的 UTC 分别处理。无法可靠分类的记录进入逐记录迁移审计；服务端按“记录标识 + 原始绝对时间”下发对应字段的 `*ReviewStatus`，视图只对该字段标记“历史时区待核对”。不得猜测平移、使用全局状态污染已确认时间或漏传状态；存在未分类的用户可见时间字段时停止发布。
6. 修改时间链路后必须使用 UTC−12、UTC、UTC+8、UTC+12 验证跨日、跨月、跨年，并确认纯日期和每日时刻不漂移。时间审计必须拦截 WXML 原始字段、页面私有本地化格式化和可见 ISO 字符串。
7. 可证明由旧 UTC+8 数据库墙上时间生成的字段减 480 分钟；混合来源字段只物化逐记录待核对账本，不自动平移。存在未解决记录时 cutover 必须为 `review_pending` 且展示映射数等于未解决数；只有未解决数为零才允许 `verified`。迁移账本和 UTC cutover 必须分别校验，历史关系回填必须保护 `ON UPDATE` 事实时间。

## 高危操作、安全边界与历史事实契约（不可破坏）

1. 冻结、解绑、重置凭据、撤销恢复码、永久删除和删除规则/用途必须先展示受控确认层，冻结并明确目标、范围、数量；取消零请求，执行中禁止重复提交或切换目标。
2. 页面、Behavior、组件创建的定时器、轮询、重试和 EventBus 必须保存句柄或稳定引用，并在隐藏、卸载、组织或工作上下文切换时清理；迟到回调必须再次核对上下文。
3. 文本长度按 Unicode 码点计算，前后端限制一致。管理附件的读取/预览/下载必须同时校验组织、资源归属和细粒度权限；临时上传实施单文件、单账号、全局配额和跨进程原子登记。
4. 审核轮次与签名、评分答案与规则解释、场地审批和岗位快照均为不可变历史事实。普通读取、打开表单、编辑或重提交禁止删除、覆盖或按当前配置重算历史；缺失快照时失败关闭，只能以幂等迁移和审计修复。
5. 未认证请求不得先进入大请求体解析或昂贵数据库路径；健康探针应缓存和限流，高风险限流必须跨进程共享且原子。

## 签名坐标契约（不可破坏）

手写签名固定使用“视口绝对坐标 + 普通视图实时笔迹”模型：

```text
白板 rect.left/top/right/bottom（视口 CSS px，逻辑像素）
Touch.clientX/clientY（同一视口 CSS px）
  → 裁切后保存为 screenX/screenY 绝对端点
  → 普通 view 线段实时显示（与白板同一视图层）
  → 确认时 screenX/Y - 白板 rect.left/top
  → 不可见 Canvas 仅负责导出 PNG
  → 文件预览 positionX/positionY（归一化中心点）
  → 图片/PDF 合成与 PDF 签名域
```

硬性要求：

1. 可视签名区域必须是普通 `view`，实时笔迹必须由该视图内的普通 `view` 线段渲染。严禁使用可视原生 Canvas 显示实时笔迹；微信原生 Canvas 在 Portal、fixed、transform 和页面滚动组合下可能脱离视图层。
2. 每次白板完成布局、尺寸变化或弹窗重新显示后，对可视白板重新执行 `.fields({ size: true, rect: true })`，取得当前视口 CSS px 的 `left/top/right/bottom/width/height`。同一测量周期内，白板绝对边界是触点和笔迹的唯一屏幕范围；不使用固定偏移值、DPR、rpx 猜测或 scrollTop 补偿。
3. 每个触点只读取 `Touch.clientX/clientY`，裁切到当前白板绝对边界后保存为 `screenX/screenY`。每条实时线段的两个端点都必须保持绝对坐标；渲染到白板子视图时，仅根据当前 rect 在生成样式的最后一步减一次 `rect.left/top`，不得持久化局部坐标样式。
4. 页面滚动、弹窗定位和设备尺寸不得参与笔迹换算。白板 rect 与 Touch 都使用同一视口 CSS px（逻辑像素）单位，因此无论弹窗位于 Portal、fixed、absolute 或滚动页面，只要白板完成布局后重新测量，绝对坐标关系保持一致。
5. 原生 Canvas 只能作为不可见导出器，不得绑定触摸、不得承担实时显示。确认签名时，将已保存的绝对端点分别减去白板 `rect.left/top`，绘制到与白板 `width/height` 相同的 1:1 buffer；导出尺寸不得乘 DPR。
6. 初始签名图片在白板中用普通 `image` 显示，导出时再绘制到隐藏 Canvas。清除操作必须同时清除普通视图线段和初始图片状态。
7. 白板、实时笔迹层和线段都必须 `overflow:hidden` 或受白板裁切；任何笔迹都不能进入按钮、弹窗外壳或背景。
8. 文件定位继续只保存实际预览图中的归一化中心点 `positionX/positionY ∈ [0,1]`。预览签名保持原始宽高比；图片、PDF 和 PDF Widget 每个目标坐标系只转换一次。
9. 改动后必须用真实鼠标或触控事件从明确起点拖到明确终点，检查指针轨迹与普通视图笔迹逐点重合。禁止直接调用组件方法、隐藏 Canvas 或绘图 API生成测试线冒充现场验收。

禁止事项：

- 禁止恢复可视原生 Canvas 实时笔迹；
- 禁止直接使用 `Touch.x/y`、`pageX/pageY`；
- 禁止把 scrollTop、状态栏高度、标题栏高度、弹窗 top 或设备经验偏移写进笔迹坐标；
- 禁止 DPR buffer、`ctx.scale(DPR)`、`setTransform(DPR)` 和 rpx 自动识别；
- 禁止把局部坐标作为实时笔迹的事实数据；局部坐标只能在普通视图样式或最终导出时由绝对坐标投影得到；
- 禁止用固定高度代替签名图片真实宽高比；
- 禁止只验证导出 Canvas，而不验证真实触点和屏幕实时笔迹。

## 审批步骤详情展开 UI 契约

- 审批步骤卡展开详情必须位于同一张 `.flow-info` 卡片内部，禁止放在卡片外作为兄弟节点。展开时同时给可视卡片添加 `.flow-info-expanded`；不能只给祖先添加 `.flow-node-expanded` 后依赖选择器先后顺序。`.flow-info-expanded` 的优先级必须稳定覆盖 `.flow-node-done/.flow-node-rejected .flow-info`，强制切换为白色玻璃层，状态色只允许出现在收起态。
- 基础流程卡、展开层、提示和详情排版仅在 `subpackages/main/styles/home.wxss` 维护一份；审核与场地页面不得复制第二套 `.flow-expand-*`、`.flow-detail-*` 样式。承载流程卡的自定义组件使用 `styleIsolation: apply-shared` 接受调用页样式，组件 WXSS 禁止直接 `@import` 页面级共享文件，否则标签选择器会在组件编译域产生警告且共享规则不稳定。审批意见只在展开详情中显示。修改后必须逐一核对已通过、已驳回的收起/展开四种视觉状态，并确认标题、状态标签、处理人、处理时间和意见顺序一致。

## 审批人员选择 UI 契约

场地借用管理端的“待我审批”必须作为顶部管理页签独立呈现，不得继续嵌在“借用管理”的筛选卡中。待我审批页内的“审批历史”入口使用紧凑链接式控件；历史列表每次从当前组织全部借用记录实时匹配当前工作上下文、当前岗位和当前操作者的不可变审批快照，不建立单独历史表，并明确显示处理结果。旧记录缺少岗位快照时必须失败关闭并提示历史授权信息不足，禁止按自然人、管理员身份、`hr_info` 或当前岗位兼容放行。历史页不放刷新按钮；一条借用只保留一张可点击卡片，处理时间、审批步骤和意见进入详情页，详情页必须展示本人处理的全部步骤及后续审批进展。

普通用户端必须在“待我审批”页签内提供可见的“审批历史”入口，不得把入口放在“我的借用”页或借用记录区域。审批历史详情、日程点击详情和我的借用点击详情必须复用同一个借用详情组件与数据形状。服务端必须先完成当前组织、当前工作上下文、当前岗位和当前操作者的历史权限匹配，再返回详情。详情进度必须同时携带全部 `flowSteps` 与 `snapshots`，显示已完成步数取数据库当前步骤与快照最高已完成步骤的并集并限制在总步骤内，确保后续步骤完成后不会停留在旧进度。

- 模板审批修改界面只为模板明确允许指定的第一步显示“指定/修改指定”；未允许的步骤不得出现伪入口。
- “指定/修改指定”入口必须和第一步步骤编号、审批条件、动作展示在同一张步骤预览卡内；已指定的一人或多人直接使用紧凑气泡展示并提供移除操作，禁止单独绘制第一步审批人卡片。
- 驳回重提交后的每一轮审批沿用模板原始候选条件；当前审批人收到某一步时，只在下一步的允许指定开关开启时显示人员选择器。
- 人员选择器只展示当前组织、当前步骤原始条件筛选后的岗位候选人，部门、身份类别、职能组筛选属于弹窗内部即时筛选，不得请求管理员专用目录接口。审核模板条件、首步指定和后续指定的最小选项必须是“人员 · 岗位”，完整显示岗位标签并同时提交人员 ID 与岗位 ID；同一人的不同岗位不得合并。
- 客户端限制不能替代服务端校验；服务端必须校验步骤开关、当前审批权限、组织隔离和候选人是否满足模板原始条件。

## 小程序分包与语言资源契约

- 主包启动壳物理放在 `miniprogram/subpackages/main/pages/**`，登录页和门户页注册在 `app.json.pages` 顶层；`subpackages/main` 不得写入 `app.json.subPackages`。包归属以注册位置为准，不以目录名为准。
- 所有业务页面统一注册在 `subpackages/<模块名>/pages/**` 的 `app.json.subPackages` 中。跨模块工作台组合页也必须位于独立业务分包，不得直接回到顶层主包。
- 分包只能引用自身分包或主包资源，禁止直接引用其他业务分包的 JS、JSON、WXML、WXSS 或组件；跨模块共享样式统一放在 `miniprogram/subpackages/main/styles/**`，并由兼容性审计检查相对路径和包边界。
- WXML 结构复杂度属于 UI 可维护性硬约束：查询控制卡、复杂弹窗、详情面板等独立语义区应拆为自定义组件。不得让单页模板增长到 Glass-Easel 生成保留字变量或无法解析；必须执行 `scripts/wechat-template-runtime-audit.js`，在安装微信开发者工具的环境中对生成代码二次语法解析，并保留无编译器 CI 的元素数量上限。组件通过明确 properties/events 传递状态与动作，使用 `styleIsolation: apply-shared` 复用已审计页面样式，不得复制整页 WXSS。
- 迁移页面时必须同步更新 `app.json`、所有可信路由、上下文守卫、服务端通知/待办目标 URL、测试读取路径和 WXSS 导入路径；旧主包业务地址不得继续出现在生产调用链中。
- 提示、指引、校验、空状态、通知、确认层和导出标题等用户可见常量只能存在于对应 `locales`。变量值不迁入 locale，业务代码通过格式化函数传入；CSV 列别名、状态码、路由和内部日志保持代码语义。
- 迁移/生成 locale 时必须合并当前文件与 Git 基线中的既有资源，不能以单次扫描结果覆盖旧键；迁移完成后必须运行资源审计和受影响模块回归测试。
- 语言门禁必须包含 `--strict-localization` 和 `--strict-guidance`；未通过前不得提交或发布。

## 场地借用规则编辑器可操作性契约

- 规则编辑弹窗固定为“标题 / 可滚动正文 / 底部操作栏”三段，正文必须使用直接子级 `scroll-view.ui-dialog-body`，底部保存按钮必须使用 `ui-dialog-footer`。标题、正文和底部操作栏通过 flex 按实际内容动态分配高度；只允许基于视口安全区计算的动态上限，禁止固定内容高度、固定像素偏移或固定翻页尺度，允许 `max-height: calc(100vh - 安全区)` 作为溢出保护。
- 步骤条件参考审核子应用模板步骤展开样式：每条条件使用紧凑卡片和左侧强调线，部门、职能组、身份类别在卡片内按语义行展示并可自然换行，禁止大块空白。
- 条件为“指定”时，步骤卡片、步骤编辑器和条件编辑器必须显示实际部门、职能组、身份类别名称，禁止只显示“指定部门/指定职能组/指定身份类别”。展示名称必须由统一字典预计算，字典异步返回后刷新；名称过长允许在标签内换行。
- 条件编辑器打开时，步骤编辑器必须隐藏；部门、职能组、身份类别使用统一纵向条件选项卡，选择结果紧随对应条件显示。
- 子编辑器关闭状态使用明确的 `null`，禁止用 `undefined` 作为小程序视图清除信号；取消不写回，保存先写回上级步骤/规则列表，再关闭子编辑器。
- 必须保留原有字段、选择器和步骤操作；在手机、Pad 竖屏、Pad 横屏中都要能滚动到底部并操作取消、添加、编辑和保存。
- 步骤条件展示采用条件卡信息层级：条件关系为小标题，部门、职能组、身份类别分别单行展示，语义标签与实际范围值分列，范围值使用深色正文并允许自然换行；禁止将多项条件压成连续蓝色小号文字。
- 添加/编辑步骤或条件后，必须用滚动容器的语义定位把对应编辑器带入可视区，禁止固定 scrollTop、固定偏移或让用户自行寻找；定位在内容渲染完成后触发，关闭时清理定位状态。
- 验收必须包含真实点击链路：打开规则编辑器、添加步骤、编辑条件、滚动到底、取消、保存；未完成现场验证不得宣称通过。
- 借用时间窗口放在场地借用策略层，开放和截止可以独立选择不设置、按天数或按小时/分钟；不设置的语义必须在界面明确说明，且由服务端按借用开始时间动态校验。
- 用户端场地卡片把开放提交与截止提交作为与“需审核/直接通过”同级的彩色状态气泡，放在同一个可换行状态行中；文案使用“开放提交 不限/开放提交 X 日前/开放提交 X 小时 Y 分钟前”和“截止提交 借用前/截止提交 X 日前/截止提交 X 小时 Y 分钟前”，禁止嵌套浅色块、冒号堆叠或“开放：不限制前”等内部拼接语法。
- 用户端日程的整列点击、日期 picker、时间输入和拖动时间条必须复用同一套“开放时段、当前时间、借用窗口、占用冲突”判定；无效操作不得静默打开或自动跳到其他时间，需保留上一次有效值并反馈原因。
- 借用时间窗口在规则管理中必须作为独立并列设置项直接编辑保存，不得放进借用规则或审批步骤的嵌套编辑弹窗；展示沿用现有列表卡片、字段、picker 和按钮契约。
- 活动占用先选择每天/每周/每月/每年周期，再在周期内部互斥勾选“按生效时间范围”或“按重复次数”；不勾选表示不限周期范围。仅展示当前选项需要的字段，不得同时堆叠两套配置。不得把时间范围或重复次数做成新的周期类别。服务端统一展开具体占用片段，跨日片段按日裁切，日程和借用冲突校验必须使用同一结果。
- 活动规则记录卡片与用户端/管理端日程活动块都必须可点击，并用统一详情弹窗展示活动名称、场地、本次占用时间和重复规则，不能出现占用块点击无反应。
- 通知列表在有通知时提供二次确认的“全部清除”，只删除当前消息范围的通知，不得影响实时待我审批事项。
